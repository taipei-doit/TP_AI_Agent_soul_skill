# 資訊安全

適用：所有程式。

> 標記說明：〔法〕法律明文規定；〔府〕行政院或臺北市政府的指引、規定；〔建議〕本規範建議的做法。法規原文與來源見 `legal-sources.md`。

### 一、這些事由你負責，不必問承辦人

承辦人不需要知道程式攻擊手法的名稱，也不應該由他決定要不要防範。下列做法是預設，寫程式時直接做：〔建議〕

| 要防的事 | 白話說明（需要向承辦人說明時用） | 你要做的 |
|---|---|---|
| SQL 注入 | 有人在欄位輸入特殊文字，偷看或刪掉資料庫的資料 | 參數化查詢或 ORM |
| XSS（跨站腳本） | 有人在欄位輸入一段程式，讓其他看到頁面的人被盜用帳號 | 輸出時跳脫，前端用 `textContent`，樣板引擎開啟自動跳脫 |
| CSRF（跨站請求偽造） | 別的網站偷偷用您已登入的身分送出資料 | 表單帶 CSRF 代碼，Cookie 設 `SameSite` |
| 權限繞過 | 知道網址就能看到不該看的資料 | 每個後端功能都檢查身分與權限 |
| 密碼外洩 | 資料庫被偷時密碼直接曝光 | 密碼雜湊儲存（見 `systems.md` 三） |
| 機密寫在程式裡 | 程式碼外流時連帶外流密碼、金鑰 | 改用環境變數或設定檔，不放進版本控制 |
| 檔案上傳攻擊 | 上傳偽裝的程式檔，在主機上執行 | 依 `systems.md` 四 |
| 試算表公式注入 | 匯出的檔案用 Excel 打開時自動執行公式 | CSV：儲存格開頭是 `=`、`+`、`-`、`@` 時加單引號；`.xlsx`：以文字型態寫入 |
| 套件來源不明 | 用到有後門或危害國家資通安全的產品 | 依 `tech-stack.md` 五；〔法〕資通安全管理法第 11 條 |

做完依 `verification.md` 測試，並照實回報。向承辦人說明時用中間那一欄的白話，不用左邊的術語。

### 二、程式寫法

- 畫面上顯示個資時預設遮蔽，例如「王○明」「A12****789」「0912-***-678」。〔建議〕
- 個資不得寫進前端程式、瀏覽器的 localStorage、網址參數、log 檔。〔建議〕
- 測試資料一律用假資料（「王小明」「0912-345-678」），不得用真實民眾資料。〔府〕行政院生成式 AI 參考指引第四點
- 密碼、金鑰、資料庫連線字串不得寫在程式碼裡，改用環境變數，並把 `.env` 加進 `.gitignore`。
- 使用者輸入的內容一律當作不可信任：
  - 顯示到畫面時用 `textContent`，不得用 `innerHTML` 拼接。
  - 資料庫查詢用參數化查詢，不得字串拼接 SQL。
  - 前端和後端都要檢查格式。
- 錯誤頁不得顯示程式錯誤細節（堆疊資訊、資料庫訊息）。
- 不使用追蹤性 Cookie。需要 Cookie 時，設定 `Secure`、`HttpOnly`、`SameSite=Lax`。

### 三、上線設定

部署到正式主機時，應設定下列 HTTP 標頭（由機關資訊單位或主機管理者協助設定，交付說明要提醒）：

```
Strict-Transport-Security: max-age=31536000; includeSubDomains
Content-Security-Policy: default-src 'self'; img-src 'self' data:; style-src 'self'; script-src 'self'; frame-ancestors 'none'; base-uri 'self'; form-action 'self'
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
Referrer-Policy: strict-origin-when-cross-origin
```

為了能套用上面這組 CSP，程式裡不要寫 inline `<script>` 和 `style="..."`，一律放在獨立的 `.js`、`.css` 檔。

其他提醒：

- 全站使用 HTTPS。
- 對外公開的系統，上線前應做弱點掃描；依機關的資通安全責任等級，可能還需要滲透測試。請承辦人洽機關資訊單位。〔府〕系統開發與委外，依《臺北市政府資通安全管理規定》辦理。
- 有管理後臺的，必須有登入和權限控管，不能只靠「網址不公開」。
- 保留必要的存取紀錄（時間、來源 IP、操作），寫明保存期限。
