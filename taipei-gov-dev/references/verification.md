# 檢查與回報

適用：所有工作。完成後依本檔執行適用的檢查，照實回報。

> 標記說明：〔法〕法律明文規定；〔府〕行政院或臺北市政府的指引、規定；〔建議〕本規範建議的做法。法規原文與來源見 `legal-sources.md`。

### 一、原則

1. **安全是預設做法，不是選項。** 輸入檢查、參數化查詢、輸出跳脫、權限檢查、CSRF 防護這些做法，寫程式時就要做，不必問承辦人，也不必向承辦人解釋術語。〔建議〕
2. **做完要實際測。** 能在你的環境執行的檢查，就實際執行；不要只看程式碼就說「應該沒問題」。〔建議〕
3. **照實回報。** 每項檢查只能是下列四種結果之一：
   - **通過**：實際測過，結果符合。
   - **未通過**：實際測過，結果不符合。先修正再測；修不好的，寫明問題和影響。
   - **未測**：沒有測，並寫明原因（例如「需要正式主機才能測」「需要資訊單位的掃描工具」）。
   - **不適用**：這項工作沒有這個功能，並寫明原因。
4. **不得誇大。** 〔府〕
   - 不得把未測或未通過的項目說成通過。
   - 不得用「安全」「合格」「符合法規」「通過無障礙檢測」這類總結式說法。改說做到了什麼、測了什麼，例如「已用自動工具檢查無障礙，0 個問題；尚未送 Freego 檢測」。
   - 自動檢查工具（例如 axe-core）的結果，不等於通過數位發展部的無障礙檢測或取得標章；你自己做的安全測試，不等於弱點掃描或滲透測試。
5. **測試只用假資料。** 不用真實民眾資料測試。〔府〕

### 二、各類工作要做的檢查

工作類型見 SKILL.md「二、判斷工作類型」。一件工作屬於好幾類時，各類的檢查都要做。

| 類型 | 至少要做的檢查 |
|---|---|
| A. 文件與資料處理工具 | 用假資料或範例檔實際執行一次；確認原始檔沒有被修改；錯誤訊息是白話。Excel、CSV：筆數核對（讀入、輸出、排除），放入有問題的資料（空白列、開頭是 0 的號碼、日期、全形半形、重複資料）確認處理正確。Word、PowerPoint、PDF：輸出檔能正常開啟，版面、字型、頁碼沒有跑掉，套印份數和名單筆數一致，要對外的檔案已移除追蹤修訂、註解、備忘稿與作者資訊 |
| B. 小工具畫面 | A 類的檢查；在瀏覽器打開沒有錯誤訊息；只用鍵盤可以操作；斷網後仍可使用（若宣稱不連網路） |
| C. 對外資訊網頁 | 瀏覽器主控台沒有錯誤；桌機（1280px 以上）與手機（390px）寬度都沒有左右捲軸；放大 200%（或 640px 寬）沒有左右捲軸；按 Tab 第一個是「跳到主要內容」；文字對比符合目標等級；有工具時用自動無障礙檢查（例如 axe-core）；所有連結都能正常開啟 |
| D. 表單、報名、申請 | C 類的檢查；空白送出與格式錯誤時，錯誤訊息正確、焦點移到第一個錯誤欄位；連按送出只建立一筆；個資告知六項齊全；後端也會檢查格式 |
| E. 系統 | D 類的檢查；未登入不能進後臺；用 A 角色的帳號直接呼叫 B 角色或其他機關的功能，後端會擋下；沒有 CSRF 代碼的送出會被拒；登入錯誤會鎖定；登出後舊的 session 無效；有名額時，多人同時搶最後一個名額不會超收；有上傳時，上傳不允許的檔案類型、改副檔名的檔案、超過大小的檔案都會被擋；匯出 CSV 有防公式注入 |
| F. 系統本身用到 AI | 依上面的類型檢查，另確認畫面有告知民眾正在使用 AI、有轉接真人的管道 |

做不到的檢查（例如沒有瀏覽器可以測、需要正式主機），標為「未測」並寫明原因，列入交付說明的「正式給別人使用前還要做什麼」。

測試環境和承辦人實際使用的環境不同時（例如你在 Linux 上用 Chromium 測，承辦人用 Windows 的 Edge），功能測試的結果照實寫「通過」，另外列一項「在承辦人實際環境操作」為「未測」，並請承辦人先用假資料試一次。

### 三、交付前檢核清單

把下面清單中**適用的段落**複製到回覆裡，逐項標示。

- `[x]` 已做到，並已檢查
- `[ ]` 還沒做到（先修正，或在交付說明寫明原因）
- `[—]` 不適用，後面用括號寫原因，例如「[—] 檔案上傳規定（本系統沒有上傳功能）」

整段不適用時（例如 Excel 工具沒有網頁畫面），寫一行「【畫面與識別】不適用：本工具沒有網頁畫面」即可。適用段落中不適用的單項，不要硬打勾，也不要直接刪掉。

[ ] 資料在本機處理，沒有上傳到外部服務
