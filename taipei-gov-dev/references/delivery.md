# 交付說明

適用：所有工作。完成後，用本檔的格式向承辦人說明。

### 一、寫給誰、怎麼寫

交付說明是寫給**不懂程式的承辦人**看的。他只需要知道四件事：

1. 能不能正常使用
2. 資料存放在哪裡
3. 有哪些限制
4. 正式給別人使用前還要做什麼

寫法：

- 用承辦人聽得懂的話。不寫 SQL 注入、XSS、CSRF、CSP、session 這類術語；要提到安全措施時，講它保護了什麼（「別人沒辦法冒用您的帳號送出資料」）。
- 技術細節（安裝套件、程式架構、設定方式、維護方法）寫在專案資料夾的 `README.md`，給之後接手的人或資訊單位看，不要塞進交付說明。
- 檢查結果依 `verification.md` 照實寫：測過且通過的寫「已確認」，沒測的寫「尚未確認」並說明原因，有問題的直接講。不寫「完全安全」「已符合所有規定」。
- 不知道的資訊用〔請填入〕，不要自己編。
- 用語依 `writing.md`。

### 二、範本

依工作類型刪去不適用的項目。小工具的說明可以很短，系統的說明會比較長，但都依這四段的順序寫。

```
一、能不能用
　　（一）做好了什麼：〔一兩句話，例：完成「報名名單整理工具」，可以把各梯次的報名 Excel 合併成一份，並找出重複報名的人。〕
　　（二）怎麼使用：
　　　　〔一步一步寫，每個指令都要能直接複製貼上，例：
　　　　1. 把要整理的 Excel 檔放進「輸入」資料夾。
　　　　2. 在「執行整理.bat」上按兩下。
　　　　3. 整理好的檔案會出現在「輸出」資料夾。〕
　　（三）我確認過的事：
　　　　〔例：
　　　　1. 已用假資料測試，100 筆名單合併後筆數正確，3 筆重複資料都有找出來。
　　　　2. 原始檔案不會被修改。〕
　　（四）尚未確認的事：
　　　　〔沒有就寫「無」。例：還沒用超過 1 萬筆的檔案測試過，檔案很大時可能需要等比較久。〕

二、資料存放在哪裡
　　〔例：
　　（一）工具只在您的電腦上執行，資料不會上傳到網路。
　　（二）整理好的檔案存在「輸出」資料夾，含有民眾姓名與電話，請存放在機關規定的位置，用完依保存期限刪除。〕
　　〔系統類，例：
　　（一）報名資料存在系統的資料庫檔案（〔位置〕），目前只在您的電腦上。
　　（二）畫面上的姓名與電話會部分遮蔽，要看完整資料須填寫理由，系統會留下紀錄。
　　（三）資料保存期限目前標示〔請填入〕，請確認後告訴我，我會設定到期自動刪除。〕

三、有哪些限制
　　（一）〔做不到的事，例：每個檔案的第一列必須是欄位名稱。〕
　　（二）〔我做的假設，請確認，例：手機號碼相同就視為同一人。〕
　　（三）〔需要您補上或確認的地方，例：Logo 取自〔來源網址〕，請確認是最新版本；頁尾地址取自〔來源網址〕，請確認；個資告知的蒐集目的與保存期限目前標示〔請填入〕。〕
　　（四）〔和市府範本不同的地方，沒有就省略。〕

四、正式給別人使用前還要做什麼
　　〔依使用範圍寫，例：
　　只有您自己用：不需要另外處理。
　　給科內同仁用：請同仁照「一、（二）」的步驟操作；檔案含個資時，提醒同仁存放位置。
　　給民眾使用或放到網路上：
　　（一）這個系統有〔登入／管理後臺／檔案上傳／個人資料〕，上線前要請機關資訊單位協助：安排主機、設定加密連線、建立備份並測試還原、做弱點掃描。
　　（二）請用 Freego 做無障礙檢測。我只用自動工具檢查過，不代表通過檢測。
　　（三）〔需要申請的事，例：若要改用臺北通或市府單一簽入登入，請及早向資訊單位申請。〕〕

五、AI 協助產出說明
　　（一）本〔工具／網頁／系統〕由〔AI 工具名稱、模型名稱與版本，照工具顯示的名稱寫〕協助產出，請親自檢查、修改，送主管審閱後再使用。
　　（二）依臺北市政府使用人工智慧作業指引，對外公開前請以近似度比對軟體比對程式碼；與開源軟體相同或近似的部分須遵守其授權條款，與第三方軟體相同或近似的部分，須以人工大幅修改或重新產生。
```

### 三、各類工作的重點

| 類型 | 「能不能用」要寫 | 「資料存放」要寫 | 「正式使用前」要寫 |
|---|---|---|---|
| A. 文件與資料處理工具 | 怎麼執行、筆數核對結果 | 資料是否只在本機、輸出檔存在哪裡 | 給同仁用時怎麼操作；檔案含個資的保管方式 |
| B. 小工具畫面 | 怎麼打開 | 資料是否只在本機、會不會存在瀏覽器裡 | 同 A |
| C. 對外資訊網頁 | 怎麼打開預覽、檢查結果 | 有沒有蒐集任何資料（通常沒有） | 上傳到機關網站主機、無障礙檢測 |
| D. 表單、報名、申請 | 怎麼測試報名流程 | 報名資料存在哪裡、保存多久 | 主機、加密連線、無障礙檢測、個資告知的待填內容 |
| E. 系統 | 怎麼啟動、怎麼建立第一個管理者帳號 | 資料庫在哪裡、誰看得到什麼、操作紀錄 | 資訊單位評估、備份、弱點掃描、登入方式申請 |

### 四、README.md（給接手的人）

要存資料的網頁與系統（`tech-stack.md` 第二級以上），以及需要安裝的工具，專案資料夾裡要有 `README.md`，寫給之後接手維護的人或資訊單位，內容包括：

- 用了哪些技術與套件（含版本）
- 怎麼安裝、啟動、停止、更新
- 設定檔與環境變數
- 資料存在哪裡、怎麼備份與還原
- 帳號與權限設計
- 已知的限制與待辦事項
