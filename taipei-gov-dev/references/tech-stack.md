# 技術選擇

適用：要做網頁或系統時。資料處理工具見 `data-tools.md`。

一、**依需求選技術，夠用就好。** 技術沒有限制，Node.js、建置工具、前端框架、資料庫都可以用，重點是選「能滿足需求的最簡單做法」。越簡單，承辦人越容易看懂、修改，之後接手的人也越好維護。在 SKILL.md 工作流程的「（二）說明判斷與做法」，要說明選用哪一級及理由。

| 級別 | 適合的需求 | 建議做法 |
|---|---|---|
| 第一級：靜態頁面 | 活動說明、公告、申請須知、表單送到既有系統 | HTML、CSS、少量原生 JavaScript。不需要安裝任何工具，用瀏覽器直接打開就能看到畫面，承辦人自己也能改文字 |
| 第二級：要存資料 | 線上報名、民眾查詢本人資料、意見回饋、簡單的案件登記 | 加上後端程式與資料庫。後端可用 Python（FastAPI、Flask、Django）、Node.js（Express 等）或機關既有的語言（PHP、Java、.NET 等） |
| 第三級：複雜系統 | 管理後臺、多種角色權限、儀表板、大量互動畫面、檔案上傳 | 後端與資料庫同第二級。畫面可以由伺服器產生（例如 Flask、Django 的樣板），互動很多時才用 React、Vue 等框架與建置工具。第三級不代表一定要用前端框架。另須遵守本規範「systems.md」 |

選擇時依下列順序考量：

1. **機關已有的平臺和技術**：機關資訊單位已經在用的語言、資料庫、主機，優先配合。系統做好之後要有人能接手維護，這比技術新不新重要。
2. **承辦人能不能自己維護**：承辦人只會改文字的，盡量停在第一級；有資訊同仁支援的，再往上。
3. **功能真正需要什麼**：只是要讓民眾填表，不需要為此架一套框架；反過來，有後臺、有多種權限的系統，也不要硬用純 HTML 拼湊。

二、**資料庫。**

- 開發和試用階段，可以先用 SQLite（一個檔案就是一個資料庫，不用另外安裝），承辦人馬上就能試用。
- 正式上線時，依機關資訊單位的規劃使用 PostgreSQL、MySQL、SQL Server 等資料庫。程式應透過 ORM 或資料庫抽象層存取資料，日後更換資料庫時才不用大改。
- 資料庫連線字串、帳號密碼放在環境變數或設定檔，不得寫在程式碼裡，設定檔也不得放進版本控制。
- 其他資料庫規定見「systems.md 九」。

三、**不論哪一級，都要遵守的事。** 使用框架或元件庫時，仍要遵守本規範的視覺、用語、無障礙、資安規定。`tp.css` 的 CSS 變數可以直接沿用到 React、Vue 等框架；使用 Mantine、Bootstrap 這類元件庫時，要把配色、字型、圓角改成本規範的設定，並移除漸層、大陰影、動畫等「web-ui.md 八、不要做的樣式」。

四、**檔案結構（第一級靜態頁面）。** 從 `templates/web/` 複製範本開始。第二、三級依所用框架的慣例安排，但仍應有無障礙聲明、隱私權政策兩頁（內部後臺改為「資料保護說明」，見「systems.md 二」），以及給接手者看的 README.md。

```
專案資料夾/
├── index.html          首頁
├── accessibility.html  無障礙聲明
├── privacy.html        隱私權及個人資料保護政策
├── assets/
│   ├── tp.css          共用樣式
│   ├── app.js          共用程式（沒有互動就不用）
│   ├── logo.svg        局處 Logo（從機關官網取得，見「web-ui.md 四」）
│   └── favicon.ico
└── README.md           說明怎麼修改、怎麼上線
```

五、**外部資源。**

- 不得載入追蹤碼、廣告碼、來路不明的外掛。
- 字型、圖示、函式庫，應下載後放在自己的 `assets/` 資料夾裡（自架），不要直接連外部 CDN。
- 真的要用 CDN 時，必須鎖定版本號，並加上 `integrity`（SRI）屬性。
- 選用套件時，確認選用的版本沒有已公開的安全漏洞，優先使用官方最新的修正版本；有些套件的修正版只放在官方網站、不在 npm 或 PyPI 上，要以官方說明為準。
- 選用套件前，先確認不是「危害國家資通安全產品」。不確定時，請承辦人向機關資安長或資訊單位確認。

六、**語系。** `<html lang="zh-Hant-TW">`。有英文版時另做英文頁，`lang="en"`。
