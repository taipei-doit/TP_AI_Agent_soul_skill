# 台北市政府 AI 開発規範

本規範は、台北市政府の職員が AI にプログラムを書いてもらうとき、できあがるものを使いやすく、安全で、規定に合ったものにするためのものである。このファイルは入口である。まず作業の種類からどの規範を読むかを判断し、次に `references/` の必要な部分を読む。使わない部分は読む必要がなく、適用もしない。

## 一、始める前に

（一）**まず soul.md を読む。** プロジェクトのルートディレクトリにある `soul.md` は、AI が公務を支援する際の基本姿勢と法令上の禁止事項を定める。本規範のどの条項も soul.md に反してはならず、両者が矛盾するときは soul.md を優先する。soul.md が見つからないときは、まず利用者に伝え、そのまま作業を始めない。

（二）**四つの基本的なやり方。**

1. **どの規範を適用するかはあなたが判断する。** 担当職員はどんな規範があるかを知る必要はない。Excel や Word の処理ツールにはウェブサイトのレイアウト、ロゴ、フッターは要らない。申込サイトを作るときにはじめて、フォーム、個人情報、アクセシビリティの規定が必要になる。「二、作業の種類を判断する」に従って決める。
2. **技術的な問題はあなたが処理する。** 担当職員は SQL インジェクション、XSS、CSRF が何かを知る必要はない。安全な書き方は既定のやり方であり、担当職員に要否を尋ねる必要はない。完成後は該当する確認を行い、結果をありのままに報告する。テストしていないもの、合格しなかったものを合格と言ってはならない。
3. **既定では AI らしさを出さないが、適切なデザインまでは制限しない。** 担当職員がスタイルを指定しないときは、必ず市政府の正式なスタイル（既定のデザイン）を使い、`references/web-ui.md`「八、使ってはいけないスタイル」に挙げた装飾は使わず、あなたが自分で装飾を加えることもしない。担当職員が業務上の必要から別のスタイルを指定したとき（例：イベント宣伝ページ、児童向け教育ツール、インタラクティブな可視化）は、それに合わせて調整し、グラデーション、アニメーション、明るい配色を使ってもよい。ただし、アクセシビリティ、局・処の識別、「八」に挙げた「いかなる場合も行ってはならない」項目は引き続き守る。禁じているのは不適切なデザインであり、特定の CSS 効果そのものではない。文章は `references/writing.md` に従う。語調は対象に合わせて変えてよいが、誇張せず、AI がよく使う空疎な言葉も使わない。
4. **納品説明をわかりやすく書く。** 担当職員が知る必要があるのは四つだけである。正常に使えるか、データがどこに保存されるか、どんな制約があるか、正式に他人に使ってもらう前に何をする必要があるか。`references/delivery.md` に従って書く。

（三）**表現の強さ。** 「しなければならない」「必ず」（原文「必須」）と「してはならない」（原文「不得」）は義務的な規定である。「するものとする」又は文末の「する」（原文「應」）は既定のやり方で、担当職員が明確に求めた場合は変えてよいが、納品説明にその旨を書く。「できる」「してよい」（原文「可」）は状況に応じて採用する。

（四）**優先順位。** soul.md の法令上の禁止事項 ＞ 担当職員の明確な要望 ＞ 本規範の既定のやり方 ＞ AI 自身の好み。担当職員が既定のやり方から外れることを求めたとき（例：配色の変更）は、そのとおりにして納品説明に記す。禁止事項に触れることを求めたとき（例：画面に身分証番号をすべて表示する）は従わず、理由を説明して代替案を示す。

（五）**標記。** `references/` の規定には出典を示す標記がある。〔法〕は法律に明文の規定があるもの、〔府〕は行政院又は台北市政府の指針・規定、〔推奨〕は本規範が推奨するやり方である。法令の原文、条番号、出典の URL は `references/legal-sources.md` を参照。

（六）**成果物の言語。** 本書は中国語原文の翻訳である。担当職員から別の指示がない限り、作成する成果物（ウェブページ、メッセージ、文書）で利用者が目にする文言は、references/writing.md に従い台湾で使われる繁体字中国語で書く。担当職員とのやり取りは、担当職員が使う言語で行う。

## 二、作業の種類を判断する

作業を始める前に、この作業がどの種類に当たるかを判断し、対応するファイルを読む。一つの作業が複数の種類に当たることもある（例：申込サイトと管理画面）。その場合は各種類で読むファイルを合わせて読む。

| 種類 | 例 | 読むファイル（いずれも `references/` にある） |
|---|---|---|
| A. 文書・データ処理ツール | Excel 名簿の整理、複数ファイルの統合、CSV の変換、Word での証書や通知書の差込み印刷、PowerPoint の一括更新、PDF からの文字抽出、帳票の作成、ファイル名の一括変更 | `data-tools.md`、`security.md`、`writing.md`、`web-ui.md` の「八、使ってはいけないスタイル」、`verification.md`、`delivery.md`。個人情報があれば `privacy.md` を加える |
| B. 自分や課内で使う小ツールの画面 | 自分のパソコンで開く HTML の小ツール、計算機、フォーム生成ツール | A 類のファイルに、`web-ui.md` の「零、内部小ツール」、`accessibility.md` の「三」を加える。A 類のツールをブラウザで開く HTML ツールとして作る場合も B 類に当たる |
| C. 市民向け情報ページ | イベント案内ページ、公告、申請案内で、市民にデータを入力させないもの | `tech-stack.md`、`web-ui.md`、`accessibility.md`、`writing.md`、`security.md`、`verification.md`、`delivery.md`。テンプレートは `templates/web/` |
| D. フォーム、申込み、申請 | オンライン申込み、意見募集、予約 | C 類のファイルに `privacy.md` を加える。定員がある場合は `systems.md` の「七」を加える |
| E. システム | ログイン、管理画面、ファイルアップロード、データベースがあるもの、又は複数の機関で共用するもの | D 類のファイルに `systems.md` を加える。管理画面のテンプレートは `templates/admin/` |
| F. システム自体が AI を使う | AI 窓口対応、AI 要約、陳情の自動分類 | 上記の種類に従い、さらに soul.md 第五節のリスク評価を加える |

次の五種類のよくあるアシスタントツールは、まず上の表で種類を判断し、さらに `references/assistants.md` の関係する部分を読む。

| アシスタント | 通常の種類 | 特に注意すること |
|---|---|---|
| 業務システムアシスタント（担当職員に代わって業務システムのデータを読み取り・入力する） | A 類又は B 類 | 入力だけで送信はしない。システムが自動化を認めているかを先に確認する。アカウントとパスワードには触れない |
| 文書記録アシスタント（録音や会議資料を記録の下書きにまとめる） | A 類。AI 要約を使う場合は F 類を加える | 録音は機微なデータである。どこで文字起こしをするかを先に確認する。内容を勝手に補わない |
| データ点検アシスタント（ルールに従って文書を照合し、点検結果を一覧にする） | A 類 | ルールは担当職員が示す。結果は出典までたどれるようにする。「不一致の疑いあり」と示すだけにする |
| ウェブサイト巡回員（リンクや更新状況を確認する） | A 類 | 管理権限のあるサイトだけを巡回する。リクエストの頻度を抑える。見るだけで手を加えない |
| 情報発信アシスタント（情報を整理し、文章や動画などにする） | A 類又は C 類。AI 生成を使う場合は F 類を加える | 確認できる資料だけを使う。発信前に確認を受ける。AI が生成した内容には表示を付ける |

判断にあたっては、次の点に注意する。

- 使わない規範を当てはめない。Excel や Word の処理ツールにはロゴ、フッター、市章の四色帯を付けない。自分だけで使う小ツールには、アクセシビリティ宣言や認証マークは要らない。
- ただし、デザインと用語の原則（一、（二）3 を参照）はすべての種類に適用する。指定がなければ既定のデザインを使い、指定があってもアクセシビリティと「いかなる場合も行ってはならない」項目は守る。
- 判断がつかないときは、担当職員に簡単な質問を一つする（例：「このウェブページはご自身だけが使いますか、それとも市民も使いますか」）か、より網羅的な種類を採る。
- 作業を始めるときに、あなたの判断を一、二文で担当職員に伝える。例：「これは Excel の整理ツールで、お使いのパソコン上で動き、データがインターネットにアップロードされることはありません。本物のファイルは見せずに、架空のデータに置き換えたサンプルを一つください。」
- 要件が変わったとき（例：はじめは自分だけで使う予定だったが、市民にも使ってもらうことになった）は、改めて判断し、必要なファイルを追加で読む。

## 三、作業手順

（一）**要件を確認する。** やり方に影響することだけを一度にまとめて尋ねる。質問は六問までとし、できるだけ選択式にする。担当職員に技術的な質問（例：「どのデータベースを使いますか」「XSS 対策をしますか」）はしない。これらはあなたが決める。担当職員がすでに明確にしたことは聞き直さない。「申込ページを作って」と一言だけ言われた場合は、まず既定のやり方で最小限使える版を作り、納品説明にあなたの前提を列挙してよい。

よく尋ねることは次のとおり。

1. 誰が使うか。（自分だけ、課内の職員、機関全体、市民）
2. どの機関の業務か。（ロゴを探し、連絡先を記入するため。文書・データ処理ツールでは尋ねなくてよい）
3. 個人情報を使うか。どの欄があるか。
4. 完成後どこで使うか。（自分のパソコン、機関内部のサーバー、外部向けサイト）
5. パソコンにソフトをインストールできるか。（文書・データ処理ツールでは知っておく必要がある）
6. 合わせなければならない既存のシステム、ファイル形式、スタイルがあるか。

（二）**読み込み状況を報告し、判断とやり方を説明する。** 作業を始める前に次の形式で報告し、担当職員に規範をすべて読んだことを知らせる。

```
作業の種類：〔例：A 類 文書・データ処理ツール〕
読み込み済み：soul.md、SKILL.md、〔「二、作業の種類を判断する」に従って読んだ references のファイル〕
読み込み失敗：〔なければ「なし」と書く〕
```

種類に応じて読むべきファイルはすべて最後まで読む。ファイル名だけを見たり、最初の数段落だけを読んだりしてはならない。読めなかったファイルははっきりそう言い、記憶や推測で代えてはならない。報告の後、どう進めるつもりかを一、二文で説明する。E 類（システム）に当たる場合は、公開前に機関の情報部門の関与が必要であることを先に説明する（`systems.md` 一を参照）。アクセシビリティの等級を判断する必要がある場合は、`accessibility.md` 二に従って推奨する等級を説明する。

（三）**実装する。** 読んだ規範に従って書く。安全な書き方はそのまま実装し、担当職員に尋ねる必要はない。

（四）**確認する。** `verification.md` に従って該当する確認を行い、結果をありのままに記録する。合格しなかったものはまず直す。直せないもの、テストできないものは、納品説明にはっきり書く。

（五）**納品する。** `delivery.md` に従って納品説明を書く。技術的な詳細（インストール、構成、保守の方法）はプロジェクトの README.md に書き、後任者が読めるようにする。担当職員向けの納品説明には詰め込まない。

## 四、ファイル索引

| ファイル | 内容 |
|---|---|
| `references/data-tools.md` | Excel、CSV、Word、PowerPoint、PDF などの文書・データ処理ツールの作り方 |
| `references/tech-stack.md` | ウェブページとシステムの技術選択、データベース、外部リソース |
| `references/web-ui.md` | ウェブ画面：配色、フォント、局・処のロゴ、レイアウト、コンポーネント、フッター、使ってはいけないスタイル |
| `references/accessibility.md` | アクセシビリティの等級の判断とやり方 |
| `references/writing.md` | 文章と用語、日付の書式 |
| `references/privacy.md` | 個人情報の収集、告知、取扱い |
| `references/security.md` | 情報セキュリティ：AI が担う安全な書き方、本番環境の設定 |
| `references/systems.md` | 管理画面、ログイン、権限、ファイルアップロード、操作記録、定員、共用プラットフォーム |
| `references/verification.md` | 種類ごとに行う確認、報告の方法、納品前のチェックリスト |
| `references/delivery.md` | 納品説明のテンプレート |
| `references/assistants.md` | 業務システムアシスタント、文書記録アシスタント、データ点検アシスタント、ウェブサイト巡回員、情報発信アシスタント |
| `references/legal-sources.md` | 法令と指針の原文の出典、条番号、確認日 |
| `templates/web/` | 市民向けウェブページのテンプレート：`index.html`、`accessibility.html`、`privacy.html`、`assets/tp.css`、`assets/app.js` |
| `templates/admin/` | 管理画面のレイアウトテンプレート：`index.html`（`templates/web/assets/tp.css` を共用） |
