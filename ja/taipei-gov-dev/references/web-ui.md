# ウェブ画面規範

適用範囲：他人が見るウェブ画面（外部向けサイト、申込ページ、管理画面）。自分のパソコンだけで使う小さなツールの画面は、本書「零、内部小ツール」の簡略な規定に従えばよい。

> 標記の説明：〔法〕法律に明文の規定があるもの。〔府〕行政院または台北市政府の指針・規定。〔推奨〕本規範が推奨するやり方。法令の原文と出典は `legal-sources.md` を参照。

### 零、内部小ツール

自分または課内の同僚が自分のパソコンで使うだけの小ツール（作業の種類 B）は、サイト向けの規定一式を適用しなくてよい。次の点だけ守る。〔推奨〕

- `templates/web/assets/tp.css` を読み込み、配色とフォントをそのまま使う。独自のデザインはしない。
- 既定では市政府の正式スタイルを用い、「八、使ってはいけないスタイル」の既定デザインに従い、独自の装飾を加えない。担当職員が別のスタイルを指定した場合は、「八」の（二）、（三）に従う。
- 文言に AI がよく使う言葉を入れてはならない。「一鍵搞定」（ワンクリックで完了）、「輕鬆完成」（簡単に完了）、「賦能」（エンパワー）、「無縫接軌」（シームレスにつながる）、「🚀 開始使用」（🚀 使ってみる）、「糟糕！出了點問題」（しまった！問題が発生しました）のような表現は一切使ってはならず、`writing.md` 二の対照表に従って公務の用語に改める。ボタンの文言は動詞にする（「開始整理」（整理を開始）、「下載結果」（結果をダウンロード））。エラーメッセージは、どうすればよいかを平易に説明する。
- ページ最上部にツール名と、用途を一、二文で書く。
- 局・処のロゴ、フッター、市章四色帯、アクセシビリティ宣言と認証マークは不要である。
- アクセシビリティは `accessibility.md` 三の基本項目を満たす。
- 後に市民向けに使う場合は、本書のすべての規定に従う。

### 一、デザインの方向性

市政府のサイトは商業製品のページではない。目を引く必要はなく、求められるのは**一目でわかり、安心して使えること**である。

- 公文書のように：機関名、明確な見出し、箇条書きの説明。「一、二、三、」で番号を振る。
- MRT の案内表示のように：重要なことは大きく、前に置く。一ページで行う主な作業は一つにする。
- 色は控えめに：大部分は白地に黒字とし、主色はボタン、リンク、見出しにだけ使う。
- 装飾は少なく：区切りには細い線を使い、カードの影、グラデーション、アニメーションで見栄えを作らない。

### 二、配色

以下は既定の配色で、文字色のコントラスト比は計算済みである。機関に独自の代表色がある場合は差し替えてよいが、**必ずコントラスト比を計算し直し**、`accessibility.md` が求める数値を下回ってはならない。

| 用途 | 変数名 | 色コード | 白地とのコントラスト | 説明 |
|---|---|---|---|---|
| 主色 | `--tp-primary` | `#0F5C86` | 7.25 : 1 | ボタン、リンク、フォーカス枠 |
| 主色（濃） | `--tp-primary-dark` | `#094463` | 10.40 : 1 | ボタンのホバー、淡色地の上のリンク |
| 主色（淡） | `--tp-primary-tint` | `#E9F2F7` | — | 背景色専用。文字色には使わない |
| 見出し墨色 | `--tp-ink` | `#16324A` | 13.21 : 1 | h1、h2、条番号 |
| 本文 | `--tp-text` | `#212529` | 15.43 : 1 | 一般の文字 |
| 補助文字 | `--tp-text-muted` | `#495057` | 8.18 : 1 | 説明、フッター、日付 |
| ページ背景色 | `--tp-bg` | `#FAFBFC` | — | 紙に近い白 |
| コンテンツ背景色 | `--tp-surface` | `#FFFFFF` | — | フォーム、表 |
| 注意帯の背景色 | `--tp-band` | `#F1F6FA` | — | 重要事項のブロック |
| 区切り線 | `--tp-border` | `#DEE2E6` | — | 装飾線専用 |
| 入力欄の枠線 | `--tp-border-input` | `#6C757D` | 4.69 : 1 | 入力欄の外枠（3:1 以上が必要） |
| エラー | `--tp-danger` | `#A61E1E` | 7.43 : 1 | エラーメッセージ |
| 成功 | `--tp-success` | `#14532D` | 9.11 : 1 | 成功メッセージ |
| 注意 | `--tp-warning` | `#6F3404` | 9.68 : 1 | 注意事項 |
| 情報 | `--tp-info` | `#0B3A66` | 11.59 : 1 | 一般的な案内 |

**市章四色**：赤 `#C64B4B`、黄 `#DFA92E`、緑 `#2F9464`、青 `#2B6CB0`。この四色は、見出しの下に置く高さ 4px の細い色帯にのみ使い、一ページに一度だけ、市政府の識別記号として表示する。広い面の背景色、ボタンの色、文字色に使ってはならない。

注意：主色 `#0F5C86` を淡色地（`#F1F6FA`、`#E9F2F7`）の上に置くと、コントラストは 7:1 未満に下がる。AAA のページを作る場合は、淡色地の上のリンクや文字には `--tp-primary-dark` を使うこと。

### 三、フォント

```css
--tp-font-sans: -apple-system, BlinkMacSystemFont, "Segoe UI", "Noto Sans TC",
                "PingFang TC", "Microsoft JhengHei", Arial, sans-serif;
--tp-font-serif: "Noto Serif TC", "PMingLiU", "MingLiU", serif;
```

- 本文はゴシック体（システムフォント）を使い、別途ダウンロードする必要はない。
- ページの大見出し（h1）と段落見出し（h2）には明朝体を使ってよい。公文書らしい改まった印象になる。明朝体は既定ではパソコン内蔵のフォントを使う。表示をそろえたい場合は、Noto Serif TC の太字（700）をダウンロードして `assets/` に置き、自前で配信してよい。
- ウェイトは 400（本文）、600（強調）、700（見出し）の三種類だけを使う。
- 本文の文字サイズは 16px 以上、行間は 1.8 程度とする。
- Inter、Poppins、Montserrat のような欧文フォントを主フォントにしない。中国語の表示がシステムフォントに戻ってしまい、外国製品に中国語をかぶせたように見える。

### 四、局・処のロゴ

各サイトのヘッダー左上には、**その局・処自身のロゴ**を置き、どの機関のサービスかが市民に一目でわかるようにする。

**入手方法**

1. ロゴは AI がその機関の公式サイトで探し、担当職員に用意させる手間をかけない。台北市の各局・処の公式サイトは多くが `機関の英語略称.gov.taipei` で、例えば資訊局（情報局）は `doit.gov.taipei`、民政局は `ca.gov.taipei` である。URL がわからない場合は、台北市政府のポータルサイト（`www.gov.taipei`）の機関一覧からリンクをたどれる。
2. 公式サイトのヘッダーのロゴは `<img>` の場合も CSS の背景画像の場合もあるので、両方を確認する。見つけたら、それが**その局・処自身の標章**であることを確かめ、フッターにある受託事業者のロゴ、協力団体のロゴ、イベントのバナーを誤って取得しない。原本ファイルを `assets/` にダウンロードする。SVG を優先し、次に十分な大きさの PNG（高さ 80px 以上。高解像度の画面でぼやけないようにするため）とする。
3. 納品説明にロゴの出典 URL を明記し、正しい最新版かどうかを担当職員にひと目で確認してもらう。
4. 次のいずれかに当たる場合は「局・処のロゴが見つからない」とみなす。
   - ネットワークに接続できない、または公式サイトにロゴの画像ファイルが見つからない。
   - 公式サイトで使われているのが台北市政府の標章や市章で、局・処専用の標章ではない。
   - 見つけた画像が正式な局・処の標章かどうか確信が持てない。

   この場合は**ロゴを置かず**、ヘッダーには機関の正式名称を文字だけで書く（例えば「臺北市政府社會局」（台北市政府社会局））。市政府の標章、市章その他の画像で代用してもならない。そのうえで担当職員に次のようにはっきり伝える。

   > 社会局の公式サイトで局専用のロゴが見つからなかったため、ヘッダーにはひとまず機関名の文字だけを置いています。貴局に正式なロゴのファイルがあれば提供してください。差し替えます。

**使用上の規定**

- 機関の正式なファイルを使わなければならない。自分で描く、AI で生成する、トレースして描き直すことをしてはならず、似たアイコンで代用してもならない。
- 色を変える、縦横比を変える、切り抜く、回転させることをしてはならず、影、枠、光彩、アニメーションも加えてはならない。
- 表示の高さは約 30〜40px とし、幅は元の比率に合わせて自動で縮尺する。ロゴの周囲には余白を取り、文字や枠に接しないようにする。
- 画像の `alt` には機関の正式名称を書く。例：`alt="臺北市政府資訊局"`。
- ロゴはリンクで囲み、そのサイトのトップページに戻れるようにする。
- 濃色地にロゴを置く場合は、機関が提供する白抜き版を使う。白抜き版がなければ濃色地には置かない。

**台北市の市章**

- 〔法〕市章は「臺北市市徽市旗設置自治條例」（台北市市章・市旗設置自治条例）に従って使用し、所管機関は民政局である。様式を勝手に変えてはならず、商業目的や品位を欠く場所に使ってはならない。
- ウェブページでは、市章はブラウザのタブに出る小アイコン（favicon）にだけ使うことを推奨する。ヘッダーには局・処のロゴを使えばよい。
- 市章のファイルは、民政局または市政府の公式サイトが提供する正式なファイルを使うものとし、描き直してはならない。

### 五、レイアウト

```
┌─────────────────────────────────────────┐
│ 頁首：局處 Logo ＋ 服務名稱      主選單 │  高約 72px，白底，底部一條細線
├─────────────────────────────────────────┤
│ 路徑：首頁／目前頁面                     │
│                                          │
│ 臺北市政府〇〇局          ← 銜名，小字   │
│ 頁面大標                  ← h1，明體     │
│ ▬▬▬▬                     ← 市徽四色條   │
│ 一兩句話說明這頁可以做什麼               │
│ [ 主要按鈕 ]                             │
│                                          │
│ 段落標題                  ← h2，明體     │
│ ───────────────────                      │
│ 一、……                                   │
│ 二、……                                   │
├─────────────────────────────────────────┤
│ 頁尾：機關資訊、政策連結、無障礙標章     │
└─────────────────────────────────────────┘
```

- コンテンツ領域の幅：読むことが中心のページは最大幅約 40em（一行に中国語約 40 字）とし、表やダッシュボードは 72em まで広げてよい。
- ブロック間の間隔は約 48〜56px、段落間は 16px とする。
- スマートフォン表示（幅 640px 以下）では一段組みにし、ボタンは横幅いっぱいに広げてよい。
- ヘッダーを上部に固定する場合、画面の表示領域の高さが 480px 未満のとき（スマートフォンを横向きにしたときなど）は固定を解除し、ヘッダーが画面を占めすぎないようにする。

### 六、コンポーネント

**ボタン**

- ボタンは四種類に分ける。
  - 主ボタン（`.tp-btn--primary`）：主色の塗りつぶし、白字。その画面で最も主要な一つの操作に使う。
  - 副ボタン（`.tp-btn--secondary`）：白地、主色の枠。その他の操作に使う。
  - 危険ボタン（`.tp-btn--danger`）：白地、赤枠、赤字。差戻し、却下、削除、停止など、市民に不利な操作や元に戻せない操作に使う。確認ダイアログ内の最終確認ボタンは赤の塗りつぶし（`.tp-btn--danger-solid`）にする。
  - テキストリンク：「回上一頁」（前のページに戻る）、「取消並返回」（取り消して戻る）のように画面を離れる操作に使う。
- サイズ：すべてのボタンは高さ 44px 以上とし、主ボタンは 48px を推奨する。角丸 8px、太字（700）。
- 外部向けページ：一画面に置く主ボタンは一つだけにし、市民が迷わないようにする。
- 管理画面：同じブロックに置く主ボタンは一つだけにする。例えば一覧ページの「查詢」（検索）と「新增案件」（案件の新規登録）は、それぞれ絞り込み領域と見出し領域に属するので、どちらも主ボタンにしてよい。審査領域に「核准」（承認）、「候補」（補欠）、「補件」（書類補正）、「退件」（差戻し）のような並列の決定が複数ある場合は、最もよく使う一つを主ボタン、それ以外を副ボタンとし、市民に不利なものは危険ボタンにして、他のボタンから少し離して誤操作を防ぐ。
- ボタンの文言は動詞にし、押すと何が起こるかをはっきり書く：「送出申請」（申請を送信）、「查詢」（検索）、「下載申請表」（申請書をダウンロード）。
- アイコンは文字の左に置いてよいが、文字なしでアイコンだけにしてはならない。
- 送信中にボタンを `disabled` にしない（フォーカスが外れてしまう）。代わりに `aria-busy="true"` を付け、二重送信はプログラムで防ぐ。

**フォームの入力欄**

- 項目名（`<label>`）は入力欄の上に置く。必須項目には「（必填）」（必須）と書き、赤いアスタリスクだけで示さない。
- `placeholder` には例だけを入れ（例：「例：0912-345-678」）、項目名の代わりに使ってはならない。
- 入力欄の下に一行の説明を置いてよい。その場合は `aria-describedby` で関連付ける。
- エラーメッセージは入力欄の真下に置き、どこが誤りでどう入力すればよいかをはっきり書き、カーソルをその欄に戻す。
  - よい書き方：「手機號碼應為 10 碼數字，例：0912345678」（携帯電話番号は 10 桁の数字で入力してください。例：0912345678）
  - よくない書き方：「格式錯誤」（形式エラー）、「Invalid input」
- 入力欄の高さは 44px、枠線は `--tp-border-input`、角丸 8px とする。

**重要事項欄（注意帯）**

淡色地（`--tp-band`）に左側 3px の墨色の縦線を付け、「收到可疑連結？先查再點」（怪しいリンクを受け取ったら？まず確認してからクリック）のような特に注意が必要な事項を置く。一ページに一、二個までとする。

**条文式リスト**

説明事項、注意事項、誓約事項は「一、二、三、」で番号を振り、番号は明朝体の墨色にする。公文書で使い慣れた形式で、箇条記号より改まった印象があり、引用もしやすい（「請參考第二點」（第二点を参照してください））。

**表**

- 必ず `<caption>`（表題）と `<th scope="col">` を付ける。
- 表でレイアウトを組まない。
- スマートフォンで表が広すぎる場合は、外側に横スクロールを付け、文字を縮小しない。

**メッセージ表示**

送信結果や検索結果は、常設の `<div role="status" aria-live="polite">` の中に置き、スクリーンリーダーが読み上げられるようにする。エラーは `--tp-danger`、成功は `--tp-success` を使い、文字（「送出成功」（送信しました）、「送出失敗」（送信できませんでした））も添え、色だけで区別しない。

**パンくずリスト**

`<nav aria-label="路徑連結列">` とし、区切り記号は「／」、最後の項目に `aria-current="page"` を付ける。一ページだけのサイトでは省略してよい。

**外部リンク**

新しいウィンドウで開くリンクには `target="_blank" rel="noopener"` を付け、`title` に「[另開新視窗]」（新しいウィンドウで開く）と記す。

**アイコン**

アイコンが必要な場合は、単色の線画 SVG（例えば Tabler Icons、MIT ライセンス）を使い、ダウンロードしてプロジェクト内に置く。色は `currentColor` で文字色に合わせ、線幅 1.75〜2、大きさ 18〜24px とする。アイコンの横に文字がある場合は `aria-hidden="true"` を付け、アイコン単独でボタンにする場合は `aria-label` を付ける。

### 七、フッター

フッターは `<main>` の外に置く。一般的な機関のウェブページには次の項目を置くものとする。

1. 機関の正式名称（ロゴを置いてもよい）
2. 住所
3. 電話番号と受付時間（「臺北市民當家熱線 1999」（台北市民ホットライン 1999）を付記してよい）
4. プライバシー及び個人情報保護ポリシー（リンク）
5. 情報セキュリティポリシー（リンク）
6. 政府ウェブサイトのデータ公開宣言（リンク）
7. アクセシビリティ宣言（リンク）
8. アクセシビリティ認証マーク（**取得した後で**置く。「accessibility.md 六」を参照）
9. 最終更新日
10. 台北市政府ポータルサイト（リンク）

機能がごく単純な小ツールはフッターを簡略にしてよいが、**機関名、連絡先、プライバシーポリシー、アクセシビリティ宣言**の四項目は省略できない。内部の管理画面のフッターは、別に「systems.md 二」の「管理画面のフッター」に従う。

機関の住所と電話番号は、機関の公式サイトのフッターから書き写すものとする。ロゴを探すときと同様に、担当職員に別途提供を求めなくてよい。書き写した後、納品説明で担当職員に確認を求める。


### 八、使ってはいけないスタイル

本節は、Excel、Word、PowerPoint の処理ツールが出力する文書やスライド、内部小ツール、外部向けサイト、管理画面を含む、すべての種類の作業に適用する。

禁止するのは**場にそぐわないデザイン**であって、特定の CSS 効果そのものではない。そのため、次の四つの場合に分けて考える。

（一）**既定デザイン**：担当職員がスタイルを指定していない場合は、常に市政府の正式スタイルを用い、下表に挙げたスタイルを使わない。見栄えのために独自の装飾を加えることもしない。管理画面、お知らせ、申請、照会のような正式な業務画面は、すべて既定デザインを用いる。

（二）**担当職員が指定したデザイン**：担当職員が業務上の必要から別のスタイルを指定した場合、または作るもの自体が親しみやすい形式を必要とする場合（例えばイベント広報ページ、季節行事、児童向け教育ツール、インタラクティブな可視化）は、下表のグラデーション、アニメーション、明るめの配色やイラストを合わせて使ってよい。担当職員が求めるものがミニゲーム、広報イベントページ、児童向け教材であれば、スタイルが明言されていなくてもこれに当たる。ただし次の点を満たすこと。

1. 文字と背景のコントラスト比は、引き続きアクセシビリティの目標等級を満たすこと。グラデーションや画像の上の文字には別に背景色を敷き、十分なコントラストを確保する。
2. 継続または繰り返し再生されるアニメーションは一時停止できること。押したときだけ再生され一、二秒で終わるアニメーション（例えばカードをめくる動き）は、オフにできること。いずれも利用者の「視差効果を減らす」設定（`prefers-reduced-motion`）を尊重し、点滅させてはならない。
3. 絵文字とアイコンは装飾としてのみ使い（`aria-hidden="true"` を付ける）、文字による説明の代わりにしてはならない。
4. 局・処のロゴと市章は「四、局・処のロゴ」の規定に従って使用する。
5. 納品説明の「市政府のテンプレートと異なる点」に、どのデザインを採用したかとその理由を明記する。担当職員がスタイルを明言していない場合は、仮定として挙げ、担当職員に確認を求める。

（三）**いかなる場合も行ってはならないこと**：

1. 市章や局・処のロゴを描き直す、色を変える、変形させること。
2. AI で生成した画像を実際の写真や実在の人物と偽ること。
3. 文字を画像にすること（ロゴを除く）。
4. 文字のコントラスト不足、点滅するコンテンツ、止められない自動再生。
5. 文字がなくアイコンだけのボタン。
6. 業務と関係のない架空のデータや架空の推薦を入れること（例えば「已服務 10,000+ 人」（10,000 人以上が利用）、「使用者好評」（利用者の声））。

（四）**AI 生成画像**：既定デザインでは、AI で生成した画像を自分から入れない。担当職員がデザインを指定した場合や画像を求めた場合は、イラスト、説明図、装飾画像、アイコンを AI で生成してよい（プログラムで描いた SVG イラストを含む）。ただし次の条件を満たすこと。

1. **明示する。** 画像の横またはページ下部に「本頁插圖由 AI 生成」（本ページのイラストは AI で生成したものです）と記す。対外的に公開する場合は、どの AI サービスを使ったかを納品説明に明記する。〔府〕市政府の AI 作業指針（透明性）
2. **実物と偽らない。** 写実的な写真のスタイルで実際の出来事、場所、行事の現場を表現しない。識別できる実在の人物（首長、著名人、市民）を生成しない。
3. **内容を正確にする。** 衛生教育、交通、防災、操作手順のような説明図は、誤りがあると市民を誤導するので、担当職員または業務担当部署に内容の正確さを確認してもらう。
4. **AI が生成した文字を入れない。** AI 生成画像には誤字や文字化けがよくある。画像の中に文字が必要な場合は、ウェブページ上の本物の文字を重ねる。
5. **権利を侵害しない。** 特定の画家、アニメのキャラクター、ブランドのスタイルの模倣を指定しない。使用する AI サービスは、利用規約で公務利用や対外的な利用が認められていること。完全に AI で生成した画像は原則として著作権で保護されず、機関が権利を主張できない可能性があるため、メインビジュアルやマスコットのような重要な識別要素は別途デザインを依頼すること。〔府〕「經濟部智慧財產局」（経済部知的財産局）民国114年4月1日付公文
6. **偏見を持ち込まない。** 人物を単一の性別、年齢、民族の固定観念的な姿だけで描かない。〔法〕「人工智慧基本法」（人工知能基本法）第4条（公平と非差別）
7. **機微な情報を入れない。** 画像を生成する際、プロンプトに個人情報や未公開の公務情報を入れず、実在の人物の写真を AI にアップロードして加工させることもしない。〔府〕
8. **市章と局・処のロゴは AI で生成・加工してはならない**（「四、局・処のロゴ」を参照）。
9. 意味のある画像には `alt` を書き、純粋な装飾画像には `alt=""` と書く。

AI にウェブページを作らせると、同じ型のレイアウトになりやすい。青紫のグラデーション、全面の絵文字、すりガラス風のカード、中央寄せの大見出しに三列の機能カードという組み合わせである。担当職員が求めていないのにこうなると、ひと目で AI が作ったとわかり、市政府のサイトとしては品位を欠く。アクセシビリティ検査に通らないものも多い。下表は既定デザインで使わないスタイルである。

| こうしない | 理由 | こうする |
|---|---|---|
| 青紫、紫ピンク、虹色のグラデーション（背景、ボタン、文字） | 市政府の色調ではない。グラデーション上の文字はコントラストが安定しない | 白地に単一の主色 |
| 絵文字をアイコン、見出しの装飾、箇条記号に使う（🚀✨📌✅） | プラットフォームごとに見た目が違う。スクリーンリーダーが「ロケット」と読み上げる。品位を欠く | 単色線画の SVG、またはアイコンを使わない |
| すりガラス風、半透明のカード | コントラストを制御できず、古いパソコンでは表示が遅くなる | 白地の不透明色 |
| ネオンの光彩、多層の大きな影 | 視線を奪い、ゲームや広告のように見える | 細線で区切る。影は淡いもの一層まで |
| マウスを乗せるとカード全体が浮き上がる、スクロール視差、登場アニメーション | 注意をそらし、前庭感覚が敏感な利用者は気分が悪くなる | アニメーションを付けない。どうしても付ける場合は `prefers-reduced-motion` を尊重する |
| 16px 以上の大きな角丸、カプセル形のカード | 商業アプリの作法である | 8px に統一 |
| 中央寄せの特大キャッチコピー、三列の機能カード、「已服務 10,000+ 人」（10,000 人以上が利用）、利用者の声の欄 | スタートアップの製品ページの定番で、政府サイトに売り込みは不要 | 機関名、大見出し、説明、主ボタン一つ |
| 濃色のテック風背景、真っ黒の地、薄い灰色の小さな文字 | コントラスト不足で、高齢者には見えにくい | 白地に濃色の文字 |
| 文字がなくアイコンだけのボタン、placeholder を項目名代わりにする | わかりにくく、スクリーンリーダーが読み上げられない | アイコンに文字を添え、label を上に置く |
| 業務と関係のない装飾イラスト、ストックフォトのビジネスパーソン写真 | 業務と無関係で、紙面を埋めているだけ | 業務の実際の写真を使うか、画像を置かない。イラストが必要な場合は（四）に従う |
| 文字を画像にする | 拡大できず、読み上げられず、翻訳もできない | 本物の文字を使う |
| 市章や局・処のロゴを描き直す、色を変える、特殊効果を加える | 識別標章の使用規定に反する | 正式なファイルをそのまま置く |


### 九、その他の必須ページ（テンプレートは `templates/web/`）

**accessibility.html（アクセシビリティ宣言）** には次の内容を含めるものとする。

1. 本サイトは「網站無障礙規範」（ウェブサイトアクセシビリティ規範）〔AA／AAA〕等級に基づいて設計されていること。
2. アクセスキーの説明：Alt+U 上部の機能ブロック、Alt+C 中央のコンテンツブロック、Alt+Z 下部の機能ブロック（Mac では Control+Option+キー）。
3. キーボード操作：Tab で次の項目へ、Shift+Tab で前の項目へ、Enter で実行。
4. 適用範囲と、まだ適合していない項目（ある場合）。
5. 意見を寄せるための連絡先。

**privacy.html（プライバシー及び個人情報保護ポリシー）** には次の内容を含めるものとする：どの情報を収集するか、何に使うか、どれくらいの期間保存するか、Cookie を使うかどうか、本人の権利とその行使方法、連絡窓口。内容がわからない箇所は〔請填入〕（記入してください）と表示し、自分で作り上げない。

### 十、テンプレートファイル

`templates/` 内のファイルはそのままプロジェクトにコピーして使ってよい。〔 〕内は実際の内容に置き換える。

| ファイル | 用途 |
|---|---|
| `templates/web/index.html` | 外部向けページ：ヘッダー、見出し、条文式の説明、注意帯、申込フォーム（個人情報の告知を含む）、フッター |
| `templates/web/accessibility.html` | アクセシビリティ宣言 |
| `templates/web/privacy.html` | プライバシー及び個人情報保護ポリシー |
| `templates/web/assets/tp.css` | 共通スタイル。外部向けページ、管理画面、内部小ツールのすべてでこの一つを使う |
| `templates/web/assets/app.js` | フォームの検査（エラーメッセージ、フォーカス移動、二重送信の防止） |
| `templates/admin/index.html` | 管理画面のレイアウト：左側メニュー、絞り込み、表、ページ送り、確認ダイアログ |

`tp.css` を修正する場合は、配色の変数だけを差し替える。主色を変える場合はコントラスト比を計算し直す。担当職員が指定した特別なデザインは、プロジェクト独自のスタイルファイルに別に書き、`tp.css` は変更しない。
