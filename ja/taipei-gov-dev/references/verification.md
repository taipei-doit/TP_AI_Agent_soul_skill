# 確認と報告

適用範囲：すべての作業。完成後、本書に従って該当する確認を行い、ありのままに報告する。

> 標記の説明：〔法〕法律に明文の規定があるもの。〔府〕行政院または台北市政府の指針・規定。〔推奨〕本規範が推奨するやり方。法令の原文と出典は `legal-sources.md` を参照。

### 一、原則

1. **安全は既定のやり方であり、選択肢ではない。** 入力チェック、パラメータ化クエリ、出力のエスケープ、権限チェック、CSRF 対策は、プログラムを書くときに実装する。担当職員に尋ねる必要はなく、専門用語を説明する必要もない。〔推奨〕
2. **完成したら実際にテストする。** あなたの環境で実行できる確認は実際に実行する。コードを見ただけで「問題ないはず」と言わない。〔推奨〕
3. **ありのままに報告する。** 各確認の結果は次の四つのいずれかでなければならない。
   - **合格**：実際にテストし、結果が基準を満たした。
   - **不合格**：実際にテストし、結果が基準を満たさなかった。まず修正して再テストする。直せない場合は、問題と影響を明記する。
   - **未テスト**：テストしていない。理由を明記する（例：「本番サーバーがないとテストできない」「情報部門のスキャンツールが必要」）。
   - **該当なし**：この作業にはその機能がない。理由を明記する。
4. **誇張してはならない。** 〔府〕
   - 未テスト又は不合格の項目を合格と言ってはならない。
   - 「安全」「合格」「法令に適合」「アクセシビリティ検査に合格」のようなまとめの言い方をしてはならない。何をしたか、何をテストしたかを言う。例：「自動ツールでアクセシビリティを確認し、問題は 0 件。Freego による検査はまだ受けていない」。
   - 自動確認ツール（例：axe-core）の結果は、デジタル発展部のアクセシビリティ検査の合格や認証マークの取得を意味しない。あなた自身が行った安全テストは、脆弱性スキャンやペネトレーションテストを意味しない。
5. **テストには架空のデータだけを使う。** 実際の市民のデータでテストしない。〔府〕

### 二、作業の種類ごとに行う確認

作業の種類は SKILL.md「二、作業の種類を判断する」を参照。一つの作業が複数の種類に当たる場合は、各種類の確認をすべて行う。

| 種類 | 最低限行う確認 |
|---|---|
| A. 文書・データ処理ツール | 架空のデータかサンプルファイルで実際に一度実行する。元のファイルが変更されていないことを確認する。エラーメッセージが平易であること。Excel、CSV：件数の照合（読込み、出力、除外）を行い、問題のあるデータ（空行、0 で始まる番号、日付、全角・半角、重複データ）を入れて正しく処理されることを確認する。Word、PowerPoint、PDF：出力ファイルが正常に開け、レイアウト、フォント、ページ番号が崩れておらず、差込み印刷の通数が名簿の件数と一致し、外部に出すファイルからは変更履歴、コメント、ノート、作成者情報が削除されていること |
| B. 小ツールの画面 | A 類の確認。ブラウザで開いてエラーメッセージが出ない。キーボードだけで操作できる。ネットワークを切っても使える（ネットワークに接続しないとうたう場合） |
| C. 市民向け情報ページ | ブラウザのコンソールにエラーがない。デスクトップ（1280px 以上）とスマートフォン（390px）の幅のどちらでも横スクロールバーが出ない。200% に拡大しても（又は幅 640px でも）横スクロールバーが出ない。Tab を押して最初に移るのが「跳到主要內容」（メインコンテンツへ移動）である。文字のコントラストが目標等級を満たす。ツールがあれば自動アクセシビリティチェック（例：axe-core）を行う。すべてのリンクが正常に開く |
| D. フォーム、申込み、申請 | C 類の確認。空欄のまま送信したときや形式が誤っているときに、エラーメッセージが正しく、フォーカスが最初のエラー欄に移る。送信を連打しても一件しか作られない。個人情報告知の六項目がそろっている。バックエンドでも形式をチェックする |
| E. システム | D 類の確認。ログインしていなければ管理画面に入れない。A の役割のアカウントで B の役割や他機関の機能を直接呼び出すと、バックエンドが拒否する。CSRF トークンのない送信は拒否される。ログインを誤るとロックされる。ログアウト後は古い session が無効になる。定員がある場合、複数人が最後の一枠を同時に取り合っても定員を超えない。アップロードがある場合、許可しないファイル形式、拡張子を変えたファイル、サイズを超えたファイルはすべて拒否される。CSV のエクスポートで数式インジェクション対策がされている |
| F. システム自体が AI を使う | 上記の種類に従って確認し、さらに、AI を使っていることを画面で市民に知らせていること、有人対応への切替え手段があることを確認する |

できない確認（例：テストに使えるブラウザがない、本番サーバーが必要）は「未テスト」とし、理由を明記して、納品説明の「正式に他人に使ってもらう前に何をする必要があるか」に挙げる。

テスト環境と担当職員が実際に使う環境が異なる場合（例：あなたは Linux 上の Chromium でテストし、担当職員は Windows の Edge を使う）は、機能テストの結果はありのままに「合格」と書いたうえで、「担当職員の実際の環境での操作」を「未テスト」として別に一項目挙げ、まず架空のデータで一度試すよう担当職員に求める。

### 三、納品前のチェックリスト

次のリストのうち**該当する段落**を返答にコピーし、項目ごとに印を付ける。

- `[x]` 実施済みで、確認済み
- `[ ]` まだ実施していない（先に修正するか、納品説明に理由を書く）
- `[—]` 該当なし。後ろに括弧で理由を書く。例：「[—] ファイルアップロードの規定（本システムにはアップロード機能がない）」

段落全体が該当しない場合（例：Excel ツールにウェブ画面がない）は、「【画面と識別】該当なし：本ツールにはウェブ画面がない」と一行書けばよい。該当する段落の中で該当しない個別の項目は、無理にチェックを付けず、削除もしない。

[ ] データはローカルで処理し、外部サービスにアップロードしていない
