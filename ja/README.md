# 台北市政府 AI 開発ガイドライン集

[正體中文](../README.md) | [English](../en/README.md) | [日本語](../ja/README.md)

AI にプログラムを書いてもらうときは、このガイドライン集を一緒に使ってください。Excel の整理や Word 文書を扱う小さなツールから申込サイトや管理システムまで、使いやすく安全で、AI の利用に関する規定にも沿ったものができあがります。

いちばん手軽なのは、インストールをせずに、次の一文を AI 開発ツールに貼り付け、続けて作りたいものを書く方法です。

```
https://github.com/taipei-doit/TP_AI_Agent_soul_skill/tree/main/ja の README を読み、「AI への指示」に従ってガイドラインをすべて読んでから、ガイドラインに沿って次のものを開発してください：（作りたいものを書く）
```

開発のたびに自動でガイドラインを適用したい場合は、下の「インストール手順」をご覧ください。

## AI への指示

> この節は AI 開発ツールに向けて書いています。担当職員の方は読み飛ばしてかまいません。

あなたが AI で、「この README を読んでガイドラインに沿って開発してほしい」と頼まれた場合、この README を読むだけでは足りません。README は担当職員向けのインストール説明で、ガイドラインの本文は別のファイルにあります。作業を始める前に、次のことを順に行ってください。

一、**ガイドラインのファイルを取得してください。** コマンドを実行できる場合は、まずプロジェクト全体をダウンロードし（この repo を `git clone` するか、ZIP をダウンロードして展開します）、ローカルのファイルを読んでください。ダウンロードできない場合は、下記のファイルを raw 形式で一つずつ読んでください。URL の `github.com/<アカウント>/<プロジェクト>` を `raw.githubusercontent.com/<アカウント>/<プロジェクト>/main/` に置き換え、その後ろにファイルパスを付けます。例：`https://raw.githubusercontent.com/taipei-doit/TP_AI_Agent_soul_skill/main/ja/soul.md`。

二、**次の二つのファイルは、毎回必ず最後まで読んでください。**

1. `ja/soul.md`：台北市政府の職員を支援する際の基本姿勢と法令上の禁止事項です。ほかのすべての規定に優先します。
2. `ja/taipei-gov-dev/SKILL.md`：ガイドラインの入口です。その中の「二、作業の種類を判断する」に従い、今回の作業がどの種類に当たるかを判断してください。

三、**作業の種類に応じて `ja/taipei-gov-dev/references/` のファイルを読んでください。** SKILL.md の種類表に、種類ごとに読むファイルが示されています。これらのファイルも最後まで読んでください。ファイル名だけを見たり、最初の数段落だけを読んだりしてはいけません。使う可能性のあるファイルは次のとおりです。

| ファイル | 読む場面 |
|---|---|
| `ja/taipei-gov-dev/references/data-tools.md` | Excel、Word、PowerPoint、PDF などの文書・データ処理ツール |
| `ja/taipei-gov-dev/references/tech-stack.md` | ウェブページとシステム |
| `ja/taipei-gov-dev/references/web-ui.md` | 画面があるとき（「八、使ってはいけないスタイル」はすべての種類に適用） |
| `ja/taipei-gov-dev/references/accessibility.md` | 画面があるとき |
| `ja/taipei-gov-dev/references/writing.md` | すべての種類 |
| `ja/taipei-gov-dev/references/privacy.md` | 個人情報を扱うとき |
| `ja/taipei-gov-dev/references/security.md` | すべての種類 |
| `ja/taipei-gov-dev/references/systems.md` | ログイン、管理画面、アップロード、データベース、定員管理があるとき |
| `ja/taipei-gov-dev/references/verification.md` | すべての種類（完成後の確認） |
| `ja/taipei-gov-dev/references/delivery.md` | すべての種類（納品説明） |
| `ja/taipei-gov-dev/references/assistants.md` | 業務システムアシスタント、文書記録アシスタント、データ点検アシスタント、ウェブサイト巡回員、情報発信アシスタント |
| `ja/taipei-gov-dev/references/legal-sources.md` | 法令の原文を引用する必要があるとき |
| `ja/taipei-gov-dev/templates/web/` 以下のファイル | 市民向けウェブページ、内部小ツール（共通スタイル `assets/tp.css`） |
| `ja/taipei-gov-dev/templates/admin/` 以下のファイル | 管理画面 |

四、**作業を始める前に報告してください。** 担当職員が、必要なファイルをすべて読んだことを確認できるようにします。

```
作業の種類：〔例：C 類 市民向け情報ページ、担当職員が明るいデザインを指定〕
読み込み済み：ja/soul.md、ja/taipei-gov-dev/SKILL.md、〔種類に応じて読んだファイル〕
読み込み失敗：〔なければ「なし」と書く〕
```

読むべきファイルが一つでも読めなかった場合は、そのことを担当職員にはっきり伝えてください。記憶や推測でガイドラインの内容を補ってはいけません。

五、**すべて読んだら、そのまま作業に入ってください。** SKILL.md の「三、作業手順」に従います。やり方に影響する質問だけをし、担当職員がすでに明確にしたことは聞き直しません。まず既定のやり方で使える版を作ってください。

## これは何ですか？

いまは多くの AI ツール（例：Claude Code、OpenAI Codex、Gemini CLI、Google Antigravity、GitHub Copilot）がプログラム作成を手伝ってくれます。「各回の申込 Excel を一つにまとめるツールを作って」「イベントの申込ページを作って」と話しかけるだけで、AI が作ってくれます。

ただし、AI が作るものは毎回見た目が違い、青紫のグラデーションに絵文字をたくさん並べたものになりがちで、行政機関のサイトらしく見えません。また、行政機関が守るべき規定も AI は知りません。

このガイドライン集は、いわば「AI 向けの業務規程」です。作業用のフォルダに入れておくと、AI は作業前にこれを読み、次のように動きます。

- どの規定を適用するかを自分で判断します。Excel のツールならウェブサイトのレイアウトを無理に当てはめることはなく、申込サイトなら個人情報の告知やアクセシビリティなどの規定を加えます。
- 技術的な問題は AI が自分で処理します。情報漏えいや不正アクセスを防ぐ書き方は AI が最初から組み込むので、専門用語を知らなくても大丈夫です。
- 完成後は自分で確認し、何を確認済みで何が未確認かをありのままに伝えます。確認していないものを「問題ない」とは言いません。
- 納品の際には、正常に使えるか、データがどこに保存されるか、どんな制約があるか、正式に他人に使ってもらう前に何をする必要があるかを平易な言葉で説明します。
- 画面も文章も台北市政府らしい雰囲気に仕上げ、青紫のグラデーションや絵文字のような、AI にありがちな見た目にはしません。
- 「人工智慧基本法」（人工知能基本法）と、行政院・台北市政府の AI 利用に関する規定を守ります。

## どんなファイルが入っていますか？

| ファイル | 用途 | わかりやすく言うと |
|---|---|---|
| `soul.md` | AI の基本姿勢と法令上の禁止事項 | AI に「あなたは市政府のために仕事をしている。絶対にしてはいけないことはこれ」と伝えるもの |
| `taipei-gov-dev` フォルダ | 開発ガイドラインとテンプレート | AI に「作業の種類ごとに、どう作り、どう確認し、どう説明するか」を伝えるもの。入口のファイル `SKILL.md`、テーマ別のガイドライン（`references` フォルダ）、ウェブページのテンプレート（`templates` フォルダ）が入っています |
| `README.md` | インストール説明 | いまご覧になっているこの文書です |

`soul.md` と `taipei-gov-dev` フォルダの中身は AI 向けに書かれているので、中身を理解する必要はありません。興味があれば開いてみてください。

## 始める前に用意するもの

1. パソコン 1 台（Windows でも Mac でもかまいません）
2. インストール済みで、すぐに使える AI 開発ツール 1 つ。例：Claude Code、OpenAI Codex、Gemini CLI、Google Antigravity、VS Code と GitHub Copilot、Cursor。

なお、ブラウザで使う ChatGPT、Gemini、Claude のチャット画面は、お使いのパソコンにファイルを作れないため、この説明の対象外です。上に挙げたような、パソコンのフォルダの中で作業する「開発ツール」を使ってください。

まだ AI 開発ツールがない場合は、まず機関の情報部門に問い合わせ、どのツールの使用が認められているか、どのアカウントで申し込むかを確認してください。台北市政府の規定では、外部 AI サービスのアカウントは市政府の公務用メールアドレスで申し込むことになっています。

## インストール手順

### ステップ1：ガイドライン集をダウンロードする

1. 次の URL を開きます：https://github.com/taipei-doit/TP_AI_Agent_soul_skill （ログインは不要です）
2. 緑色の「Code」ボタンを押します
3. いちばん下の「Download ZIP」を選びます
4. ダウンロードが終わったら、「ダウンロード」フォルダで `TP_AI_Agent_soul_skill-main` を探します。Windows では通常、末尾の `.zip` は表示されず、ファスナーの付いたフォルダのアイコンになっています。
5. ファイルを右クリックして「すべて展開」を選びます（Windows）。Mac ではダブルクリックします。

展開するとフォルダが一つできます。開いた中に同じ名前のフォルダがもう一つあれば、さらにその中に入ります。そこにある `ja` フォルダを開くと、`soul.md`、`README.md` の二つのファイルと `taipei-gov-dev` フォルダがあります。Windows では末尾の `.md` が表示されず、`soul`、`README` とだけ表示されることがありますが、問題ありません。

### ステップ2：作業用フォルダを作る

新しいウェブページやシステムを作るたびに、新しいフォルダを一つ作ります。

1. デスクトップ（または普段使っている場所）で右クリックし、「新規作成」→「フォルダー」を選びます（Mac では「新規フォルダ」）
2. わかりやすい名前を付けます。例：`講座申込ページ`
3. 先ほどダウンロードした `ja` フォルダの中の `soul.md` ファイルと、`taipei-gov-dev` フォルダを**丸ごと**、このフォルダにコピーします

これで、フォルダの中に次の二つが入りました。

```
講座申込ページ
  soul.md
  taipei-gov-dev（フォルダ）
```

### ステップ3：AI ツールをこのフォルダで作業させる

AI 開発ツールは、作業用フォルダに「入って」はじめて、ガイドラインを読んだり、その中にファイルを作ったりできます。お使いのツールに応じて、次の表のとおり操作してください。

| AI ツール | 操作方法 |
|---|---|
| Claude Code（デスクトップアプリ） | アプリを開き、新しい会話を始める画面でフォルダを選ぶところから「講座申込ページ」を選びます |
| VS Code ＋ GitHub Copilot | VS Code を開き、上部の「ファイル」→「フォルダーを開く」で「講座申込ページ」を選びます。次に Copilot のチャット画面を開き、入力欄の下のモード選択で「Ask」を「Agent」に切り替えます（Agent モードでないとファイルを作れません） |
| Cursor | Cursor を開き、「Open Folder」を押して「講座申込ページ」を選びます |
| Google Antigravity | Antigravity を開き、「Open Folder」（フォルダを開く）を押して「講座申込ページ」を選びます |
| Claude Code、Codex、Gemini CLI（ターミナル版） | 下の説明をご覧ください |

**ターミナル版の操作方法**

「ターミナル」は、黒または白の文字だけの画面で、文字を入力してパソコンを操作するものです。

- Windows：スタートメニューで「PowerShell」を検索して開きます。
- Mac：「アプリケーション」→「ユーティリティ」→「ターミナル」を開きます。

開いたら、次のように操作します。

1. `cd` と入力し、スペースキーを一回押します。
2. 「講座申込ページ」フォルダをマウスでこの画面にドラッグすると、フォルダの場所が自動で表示されます。Enter を押します。
3. お使いのツールに応じて `claude`、`codex`、`gemini` のいずれかを入力し、Enter を押します。

（PowerShell ではなく Windows の「コマンド プロンプト」を使っていて、フォルダが C ドライブ以外にある場合は、1 で `cd /d` と入力してください。）

### ステップ4：AI に設定をしてもらう

次に、どの AI ツールでもこの二つのファイルを見つけられるよう、設定ファイルをいくつか作ります。設定ファイルの中には隠しフォルダに置くものもあり、手作業では間違えやすいので、**AI に任せるのが確実です**。

1. 下の枠の中の文章を丸ごとコピーし（GitHub のページで見ている場合は、枠の右上にコピーボタンがあります）、AI に貼り付けて Enter で送信します。

```
このフォルダで「台北市政府 AI 開発ガイドライン集」の設定をしてください。次の手順どおりに行い、それ以外の変更はしないでください。

手順一：フォルダ .claude/skills/ を作り、taipei-gov-dev フォルダを丸ごと（中のすべてのファイルとサブフォルダを含めて）その中に移動し、.claude/skills/taipei-gov-dev/ とする。

手順二：soul.md は元の場所に置いたままにし、移動しない。

手順三：AGENTS.md を作る。内容は下の「===開始===」と「===終了===」の間の文章とし、この二行は含めない。
===開始===

このプロジェクトは台北市政府の職員が使う。どの作業を始める前にも、次の二つのファイルを最後まで読み、作業の間ずっと守ること。

- soul.md：AI が公務を支援する際の基本姿勢と法令上の禁止事項。ほかのすべての規定に優先する

使っているツールが Skill 機能に対応していなくても、上記の SKILL.md を直接開いて読むこと。
作業を始める前に、作業の種類と読み込んだファイルを列挙すること。
この二つのファイルを読めない場合は、まず利用者に伝え、そのまま開発を始めないこと。
===終了===

手順四：CLAUDE.md を作る。内容は下の「===開始===」と「===終了===」の間の二行とし、目印の行は含めない。
===開始===

===終了===

手順五：GEMINI.md を作る。内容は CLAUDE.md とまったく同じにする。

手順六：.github/copilot-instructions.md を作る。内容は AGENTS.md とまったく同じにする。

手順七：.agents/rules/taipei-gov.md を作る。内容は下の「===開始===」と「===終了===」の間の文章とし、目印の行は含めない。
===開始===

description: 台北市政府 AI 開発ガイドライン
---
@[soul.md](../../soul.md)

ウェブページやプログラムを開発する前に、必ず @../../.claude/skills/taipei-gov-dev/SKILL.md を最後まで読み、その規定に従って進めること。
===終了===

終わったら、このフォルダにあるすべてのファイルのパス（隠しファイルを含む）を一行ずつ列挙して、確認させてください。
```

2. AI は作業の前に、「Do you want to create AGENTS.md?」のように英語で許可を求めてくることがあります。最初の「Yes」を選んでください。「Yes, and don't ask again」を選んだ場合は、`.claude` フォルダに `settings.local.json` が増えることがありますが、これも問題ありません。
3. 終わると、AI がファイルの一覧を表示します。表示のしかたは下と多少違うことがありますが（例：先頭に `./` が付く）、次のものがすべて表示されていれば大丈夫です（`taipei-gov-dev` フォルダの中にはほかのファイルもありますが、一つ一つ確認する必要はありません）。

```

AGENTS.md
CLAUDE.md
GEMINI.md

.agents/rules/taipei-gov.md
```

名前が「.」で始まるフォルダは隠しフォルダで、エクスプローラーや Finder では初期設定のままだと表示されません。AI が作っていないわけではありませんので、ご安心ください。表示したい場合は、Windows ではエクスプローラー上部の「表示」→「表示」→「隠しファイル」にチェックを入れます。Mac では Finder で Command＋Shift＋ピリオドを押します。

### ステップ5：AI がガイドラインを読んでいるか確認する

設定を読み直させるため、いったん AI ツールを閉じてから開き直してください。

- デスクトップアプリ：アプリを閉じてから開き、同じフォルダを選びます。
- ターミナル版：`/exit` と入力して Enter を押し（または画面を閉じ）、ステップ3のとおりにもう一度フォルダに入って AI を起動します。

そのうえで、次のように聞いてください。

```
このプロジェクトでプログラムを開発するときに守るべき規定を、三点で説明してください。
```

AI の答えに「台北市政府」「個人情報」「アクセシビリティ」「機密文書」「局・処のロゴ」といった内容が出てくれば、設定は成功です。

AI の答えがあいまいだったり、台北市政府にまったく触れなかったりする場合は、下の「よくある質問」をご覧ください。

## AI に開発を頼む

設定が終わったら、作りたいものをそのまま AI に伝えてください。具体的に伝えるほど、必要なものに近いものができます。どの機関か、何を作りたいか、データはどこから来るか、完成したら誰が使うかを伝えるのがおすすめです。

### よく使われる五種類のアシスタント

市政府でよく使われる五種類のツールを、それぞれ例文付きで紹介します。ご自分の業務に合わせて書き換えてお使いください。

**一、業務システムアシスタント**：業務システムでの繰り返しのデータ読み取りや入力を担当職員に代わって行い、担当職員が確認したうえで自分で送信します。

```
台北市政府〇〇局の担当職員です。毎週、Excel にある補助金申請のデータを
1 件ずつ〇〇業務システムの申請フォームに入力しています。約 80 件です。
欄の入力を代わりにしてくれるツールがほしいです。1 件ずつ確認して、送信は自分で押します。
```

AI は入力を手伝うだけで、代わりに送信することはありません。また、始める前に、そのシステムでプログラムによる自動操作が認められているかをシステム管理部門に確認するよう求めます。システムへのログインはご自身で行い、AI がパスワードを尋ねることはありません。

**二、文書記録アシスタント**：録音や会議資料などの元の内容から議題と結論を整理し、テンプレートに沿って記録の下書きや要約を作り、担当職員が修正・確認します。

```
台北市政府〇〇局の担当職員です。毎月の科の会議の録音とスライドがあります。
これを会議録の下書きにまとめるツールがほしいです。書式は科の会議録テンプレート（Word）に合わせます。
会議の内容に機密は含まれません。
```

録音には出席者の声と発言が含まれるため、AI はまず、どこで文字起こしをするか（例：お使いのパソコン上で動き、ネットワークに接続しない文字起こしツール）を確認します。録音をそのまま外部サービスに送ることはありません。聞き取れなかった箇所は印を付け、勝手に補うことはしません。

**三、データ点検アシスタント**：文書のデータを読み取ってまとめ、指定されたルールや参考資料と一項目ずつ照合し、点検結果を担当職員の確認用に一覧にします。

```
台北市政府〇〇局の担当職員です。受託事業者から毎月、請求資料（Excel の明細と PDF の請求書）が届きます。
品目、数量、金額が契約と一致しているかを照合し、一致しない箇所を一覧にして確認させてほしいです。
```

AI はまず、照合のルールを説明するよう求めます。点検結果には、どのファイルの何行目のどの欄かを明記し、「不一致の疑いあり」と示すだけです。差し戻すかどうかは担当職員が判断します。

**四、ウェブサイト巡回員**：ウェブサイトが正常に動いているか、内容が更新されているか、リンクが有効かを確認し、点検結果と改善案にまとめます。修正は権限のある担当者が確認したうえで行います。

```
台北市政府〇〇局の担当職員です。局のウェブサイトは 300 ページ以上あります。
毎週一回、切れたリンクや一年以上更新されていないページがないかを確認し、報告書にまとめたいです。
```

AI が巡回するのは、所属機関自身のウェブサイトだけです。アクセスの間隔も空けて、サイトに負荷をかけないようにします。ツールは確認するだけで修正はしません。修正が必要な箇所は、ご自身かサイトの管理者が対応します。

**五、情報発信アシスタント**：さまざまな情報を集めて整理し、読むための文章や動画などの内容に仕立てます。必要に応じてウェブサイトや SNS などで発信することもできます。

```
台北市政府〇〇局の担当職員です。局の最新のお知らせとプレスリリースを、
高齢者向けの短い説明と Facebook 投稿の下書きにまとめたいです。私が確認してから自分で投稿します。
```

AI は公開されていて確認できる資料だけを使い、段落ごとに出典を付けます。自動で発信することはなく、AI が生成した内容にはその旨の表示も付けます。発信の前には上司の確認を受けてください。

### そのほかの例

**Excel の名簿を整理する**

```
台北市政府社会局の担当職員です。申込名簿は回ごとに Excel ファイルになっています。
すべての回を一つにまとめ、同じ人が重複して申し込んでいるデータを見つけるツールがほしいです。
私のパソコンには自分でソフトをインストールできません。
```

AI は、欄の名前と、架空のデータに置き換えた数行の例を求めます。**本物の名簿は AI に見せないでください**。AI がその形式に合わせてツールを作ったら、そのツールで本物のファイルを処理します。データがお使いのパソコンの外に出ることはありません。

**イベント申込ページ**

```
台北市政府社会局の担当職員です。「長青学苑 秋季クラス」のオンライン申込ページを作りたいです。
市民には氏名、携帯電話番号、受講したい講座（書道、太極拳、スマートフォン入門の三つから一つ）を入力してもらいます。
申込データは受講の連絡にだけ使い、イベント終了の 3 か月後に削除します。
```

**イベント宣伝用のミニゲーム**

```
台北市政府〇〇局の担当職員です。タロットカードのミニゲームで局の〇〇業務を宣伝したいです。
画面は明るめでかまいません。遊び終わると業務のポイントと申請方法が表示されるようにしたいです。
```

### 作業の前と完成後

AI は作業の前に、「作業の種類」と、どのガイドラインのファイルを「読み込み済み」かを伝えます。そのあと、「このツールは誰が使いますか」「個人情報を使いますか」などの質問をすることがあります。ありのままに答えてください。わからないことは、わからないと伝えてかまいません。AI はまず既定のやり方で進め、あとで確認を求めます。

完成すると、AI は「納品説明」を付けて、四つのことを伝えます。正常に使えるか、データがどこに保存されるか、どんな制約があるか、正式に他人に使ってもらう前に何をする必要があるか、です。**この説明は必ず最後まで読んでください**。とくに〔記入してください〕（画面や文書の中では中国語で〔請填入〕）や「未確認」と書かれた箇所に注意してください。

## 応用：新しいフォルダすべてに自動で適用する

新しいプロジェクトをよく作り、毎回ステップ2からステップ4までをやり直すのが手間な場合は、ガイドラインをパソコンの「グローバル設定」に入れておけます。そうすると、以後はどのフォルダでも適用されます。

この方法が使えると確認できているのは、いまのところ Claude Code だけです。Claude Code に次の文章を貼り付けてください。

```
このフォルダにある taipei-gov-dev フォルダと soul.md を、私のパソコンのグローバル設定にインストールしてください。
1. taipei-gov-dev フォルダを丸ごと ~/.claude/skills/taipei-gov-dev/ にコピーする
2. soul.md を ~/.claude/taipei-gov-soul.md にコピーする
3. ~/.claude/CLAUDE.md の末尾に次の一行を追加する：@~/.claude/taipei-gov-soul.md
   （~/.claude/CLAUDE.md がなければ新しく作る）
終わったら、各ファイルの完全なパスを教えてください。
```

ほかの AI ツールでは、これまでどおりフォルダごとに設定するほうが確実です。

## よくある質問

**問：AI が README だけを読んで作業を始めてしまい、ガイドラインに沿っていないようです。**

答：ガイドラインに沿っている AI は、作業の前に「作業の種類」と「読み込み済み」のファイルを列挙します。列挙していない場合や、「読み込み済み」が README だけの場合は、次のように伝えてください。

```
README の「AI への指示」に従い、ja/soul.md、ja/taipei-gov-dev/SKILL.md と、今回の作業に必要な references のファイルを最後まで読み、読み込んだファイルを列挙してから、もう一度始めてください。
```

**問：AI がガイドラインに沿っていないようで、できたものがやはり青紫色です。**

答：次の順に試してください。

1. AI ツールを閉じてから開き直す。
2. 「まず soul.md と .claude/skills/taipei-gov-dev/SKILL.md を読み、その規定に従って作り直してください。」と直接伝える。
3. ステップ4のファイルがすべて作られているか確認する（AI に隠しファイルを含むすべてのファイルを列挙してもらう）。
4. Claude Code を使っている場合は、最新版に更新されているか確認する。

**問：使っている AI ツールが上の一覧にありません。使えますか？**

答：たいていは使えます。ほとんどの AI 開発ツールは `AGENTS.md` を自動で読みます。設定後にステップ5の確認の質問に答えられない場合は、新しい会話を始めるたびに、最初に「まず AGENTS.md を読み、その指示に従って soul.md と SKILL.md を読んでください。」と貼り付けてください。

**問：AI が、うちの機関のロゴが見つからないと言っています。**

答：AI はまず機関の公式サイトで探します。見つからない場合は、ひとまず機関名の文字で代用します。機関の公式サイトのヘッダーからロゴ画像を保存してフォルダに入れ、「ロゴのファイルは logo.png です。差し替えてください。」と AI に伝えてください。

**問：AI が、規定に反するといって頼んだ機能を作ってくれません。**

答：ガイドラインが正しく働いているということです。AI は理由を説明し、多くの場合は代わりの方法も提案します。よくある例は次のとおりです。

- 機密の表示がある文書を処理させようとした → 機密文書は規定により AI で処理できません
- 「システムが自動で判断し、資格がないことを自動で市民に通知する」機能を作らせようとした → 職員が確認する手順を加える必要があります
- 画面に身分証番号をすべて表示させようとした → 番号の一部を伏せる必要があります

ご自分の要望には法的根拠があり、作れるはずだとお考えの場合は、機関の法制部門または情報部門にご相談ください。

**問：AI に「アクセシビリティは AA と AAA のどちらにしますか」と聞かれましたが、どう答えればよいかわかりません。**

答：「おすすめでお願いします」と答えれば大丈夫です。AI がページの機能から判断します。機能が単純なページ（例：フォームが一つだけ）は最高水準の AAA を、機能が複雑なページ（例：地図がある）は少なくとも AA を推奨します。

**問：AI が作ってくれたものを、そのままインターネットに公開してよいですか？**

答：**いいえ。** まず次のことをしてください。

1. ご自身で一通り操作し、機能が正常で文言が正しいことを確かめる。
2. AI の納品説明を最後まで読み、〔記入してください〕や〔請填入〕と書かれた箇所をすべて埋める。
3. 機関の情報部門に渡し、サーバー、HTTPS、セキュリティ検査、アクセシビリティ検査の設定を手伝ってもらってから公開する。

**問：市民の本物のデータを AI に渡して、テストしてもらってもよいですか？**

答：**いけません。** 行政院と台北市政府の規定により、個人情報を外部の AI サービスに提供してはなりません。「王小明」「0912-345-678」のような架空のデータでテストしてください。AI も自分から架空のデータを使います。

**問：ファイル名は必ず `SKILL.md` でなければいけませんか？小文字にしてもよいですか？**

答：`SKILL.md`（すべて大文字）のままにしてください。Claude Code はこのファイル名しか認識しません。`soul.md` は小文字のままにしてください。

**問：ガイドラインが更新されたらどうすればよいですか？**

答：ステップ1からダウンロードし直してください。新しい `soul.md` は古いものにそのまま上書きします。`taipei-gov-dev` フォルダは、まずプロジェクトフォルダのいちばん上の階層に置き、AI に「.claude/skills/taipei-gov-dev フォルダを削除し、いちばん上の階層にある新しい taipei-gov-dev フォルダを移動して置き換えてください。」と頼んでください。

## 機関の情報部門向けの説明

- Skill は Agent Skills 形式で、フォルダは `taipei-gov-dev/` です。`SKILL.md`（YAML frontmatter、`name` は `taipei-gov-dev`）が入口で、作業の種類（文書・データ処理ツール、小ツール、市民向けウェブページ、フォーム、システム、AI 機能を含むもの）に応じて、`references/` の中から必要なガイドラインを読むよう AI に指示します。テンプレートは `templates/` にあります。AI は必要な部分だけを読み込むので、Excel のツールを作るときにウェブサイトのガイドラインを適用することはありません。
- `references/` の規定には〔法〕〔府〕〔推奨〕の標記が付いており、それぞれ法律の明文、行政院または市政府の規定、本ガイドラインの推奨を表します。法令の条番号、文書番号、原文の URL は `references/legal-sources.md` にまとめています。
- フォルダ全体は `.claude/skills/taipei-gov-dev/` に一つだけ置きます。Claude Code、VS Code Copilot、Cursor はこの場所から Skill を読み込みます。Codex CLI と Gemini CLI は `.claude/skills/` を走査しないため、`AGENTS.md`、`GEMINI.md` の指示で直接ファイルを読ませます。`.agents/skills/` に別途コピーしないのは、VS Code が同じ名前の Skill を二つ読み込むことを避け、更新時に二つの内容が食い違うことも避けるためです。
- `CLAUDE.md`、`GEMINI.md` の `@` によるインポート構文を理解できるのは Claude Code と Gemini CLI だけです。GitHub Copilot もこの二つのファイルを読みますが、文字として見るだけでエラーにはなりません。Copilot は別に `AGENTS.md` と `.github/copilot-instructions.md` から完全な指示を受け取ります。
- Google Antigravity は `AGENTS.md`、`GEMINI.md`、`.agents/rules/*.md` を読みますが、Skill は `.agents/skills/` からしか読み込みません。`GEMINI.md` の `@soul.md` もファイルパスになるだけで、内容は読み込まれません。そのため `.agents/rules/taipei-gov.md`（`trigger: always_on`）を別に作り、`@[soul.md](../../soul.md)` で soul.md の全文を埋め込み、SKILL.md はパスを示して読ませます。Antigravity の規則ファイルは一つあたり 24 KB が上限（埋め込み後で計算）なので、今後 soul.md を書き足す場合は超えないよう注意してください。
- 一覧にないその他のツール（例：Windsurf、Cline、JetBrains AI Assistant）も、多くは `AGENTS.md` に対応しています。対応していない場合は、会話のはじめに毎回「まず AGENTS.md を読み、その指示に従って soul.md と SKILL.md を読んでください」と入力してください。
- `soul.md` は `CLAUDE.md`、`GEMINI.md` の `@` インポート構文により、会話の開始時に毎回読み込まれます。Codex、Copilot、Cursor では `AGENTS.md` の指示で読ませます。Skill は AI が関係があると判断したときにしか読み込まれないため、法令上の禁止事項は毎回の会話で必ず読まれる `soul.md` に置いています。
- Codex CLI が `AGENTS.md` を読み込む既定の上限は 32 KiB です。そのため `AGENTS.md` には案内だけを置き、二つのファイルの全文は貼り込まないでください。
- 機関に独自のテーマカラー、ロゴの規定、内部のセキュリティ規定がある場合は、`taipei-gov-dev/references/` の該当ファイル（例：`web-ui.md`、`security.md`）か `soul.md` の末尾に「本機関の補足規定」という節を加えることができます。メインカラーを変えた場合は、文字のコントラスト比を計算し直してください。
