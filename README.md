# 臺北市政府 AI 開發規範包

[正體中文](README.md) | [English](en/README.md) | [日本語](ja/README.md)

請 AI 幫您寫程式時，搭配這份規範包，不論是整理 Excel、處理 Word 文件的小工具，還是報名網站、管理系統，做出來的東西都會好用、安全，也會遵守 AI 使用的相關規定。

**最快的用法**是不必安裝，直接把下面這句話貼給 AI 開發工具，再接著寫您要做什麼就可以了。

```
請先閱讀 https://github.com/taipei-doit/TP_AI_Agent_soul_skill 的 README，依照「給 AI 的指示」把規範讀齊，再依照規範幫我開發：（寫下您要做的東西）
```

如果希望每次開發都自動套用規範，請看下方的「安裝步驟」。

## 給 AI 的指示

> 這一節寫給 AI 開發工具。承辦人可以略過。

如果你是 AI，收到「閱讀這個 README 並依照規範開發」的要求，只讀這份 README 還不夠。README 是寫給承辦人看的安裝說明，規範內容放在其他檔案裡。開工前請依序完成下面幾件事。

一、**取得規範檔案。** 可以執行指令時，請先下載整個專案（`git clone` 這個 repo，或下載 ZIP 解壓縮），再讀本機的檔案。沒辦法下載時，就逐一讀取下列檔案的原始內容，做法是把網址中的 `github.com/<帳號>/<專案>` 換成 `raw.githubusercontent.com/<帳號>/<專案>/main/`，後面接檔案路徑。例如：`https://raw.githubusercontent.com/taipei-doit/TP_AI_Agent_soul_skill/main/soul.md`。

這個專案的根目錄是正體中文版。`en/`、`ja/` 是給英文、日文使用者的翻譯版，承辦人用中文和你溝通時，不要讀取這兩個資料夾，只用根目錄的檔案。如果你把專案下載到承辦人的工作資料夾，設定完成後請刪掉 `en/`、`ja/`，免得承辦人看到不認得的資料夾，不知道要不要用。

二、**下面兩個檔案一定要讀**，而且每次都要完整讀完。

1. `soul.md`：協助臺北市政府同仁的基本立場與法規紅線，優先於其他所有規定。
2. `taipei-gov-dev/SKILL.md`：規範的入口。請依其中「二、判斷工作類型」判斷這件工作屬於哪一類。

三、**依工作類型讀取 `taipei-gov-dev/references/` 裡的檔案。** SKILL.md 的類型表列有每一類要讀的檔案，這些檔案同樣要完整讀完，不能只看檔名或只讀前幾段。可能用到的檔案如下。

| 檔案 | 什麼時候讀 |
|---|---|
| `taipei-gov-dev/references/data-tools.md` | Excel、Word、PowerPoint、PDF 等文件與資料處理工具 |
| `taipei-gov-dev/references/tech-stack.md` | 網頁與系統 |
| `taipei-gov-dev/references/web-ui.md` | 有畫面時（含「八、不要做的樣式」，所有類型都適用） |
| `taipei-gov-dev/references/accessibility.md` | 有畫面時 |
| `taipei-gov-dev/references/writing.md` | 所有類型 |
| `taipei-gov-dev/references/privacy.md` | 用到個人資料時 |
| `taipei-gov-dev/references/security.md` | 所有類型 |
| `taipei-gov-dev/references/systems.md` | 有登入、後臺、上傳、資料庫、名額時 |
| `taipei-gov-dev/references/verification.md` | 所有類型（完成後的檢查） |
| `taipei-gov-dev/references/delivery.md` | 所有類型（交付說明） |
| `taipei-gov-dev/references/assistants.md` | 公務系統助手、文書紀錄助理、資料檢核助手、網站巡查員、資訊轉譯助理 |
| `taipei-gov-dev/references/legal-sources.md` | 需要引用法規原文時 |
| `taipei-gov-dev/templates/web/` 底下的檔案 | 對外網頁、內部小工具（共用樣式 `assets/tp.css`） |
| `taipei-gov-dev/templates/admin/` 底下的檔案 | 管理後臺 |
| `taipei-gov-dev/scripts/extract_zh_text.py` | 要用 zhtw-mcp 檢查網頁或程式裡的中文時 |

四、**開工前先回報**，讓承辦人確認你已經讀齊：

```
工作類型：〔例：C 類對外資訊網頁，承辦人指定活潑設計〕
已讀取：soul.md、taipei-gov-dev/SKILL.md、〔依類型讀取的檔案〕
讀取失敗：〔沒有就寫「無」〕
```

只要有一個該讀的檔案讀不到，就要明白告訴承辦人，不可以憑印象或猜測代替規範內容。

五、**讀齊後直接開工。** 依 SKILL.md「三、工作流程」辦理。只問會影響做法的問題，承辦人已經講清楚的就不必再問，先用預設做法做出可以用的版本。

## 這是什麼？

現在很多 AI 工具（例如 Claude Code、OpenAI Codex、Gemini CLI、Google Antigravity、GitHub Copilot）都可以幫忙寫程式。您只要用中文說「幫我做一個工具，把各梯次的報名 Excel 合併成一份」或「幫我做一個活動報名網頁」，它就會寫出來。

不過，AI 每次做出來的樣子都不一樣，常常是藍紫色漸層加上許多表情符號，看起來不像政府網站；它也不知道政府機關有哪些規定要遵守。

這個規範包就是一份「給 AI 看的工作守則」。把它放進您的資料夾，AI 開工前會先讀過，並且：

- 自己判斷要套用哪些規定。做 Excel 工具就不會硬套網站的版面，做報名網站才會加上個資告知、無障礙等規定。
- 自己處理技術問題。防止資料外洩、被駭的寫法，AI 會直接做好，您不需要懂這些術語。
- 做完會自己檢查，照實告訴您哪些測過、哪些還沒測，不會把沒測過的說成沒問題。
- 交付時用白話說明能不能用、資料存在哪裡、有哪些限制、給別人用之前還要做什麼。
- 畫面和文字都像臺北市政府的風格，不會出現藍紫色漸層、表情符號這類 AI 常見的樣子。
- 遵守《人工智慧基本法》和行政院、臺北市政府的 AI 使用規定。

## 開始之前，您需要準備

1. **一部電腦**（Windows 或 Mac 都可以）
2. **一個 AI 開發工具**，而且已經安裝好、可以使用，例如 Claude Code、OpenAI Codex、Gemini CLI、Google Antigravity、VS Code 加上 GitHub Copilot、Cursor。

請注意：瀏覽器裡的 ChatGPT、Gemini、Claude 聊天網頁，沒辦法在您的電腦上建立檔案，不適用這份說明。一定要用上面這類會在您電腦資料夾裡工作的「開發工具」。

還沒有 AI 開發工具的話，請先洽詢機關資訊單位，確認機關允許使用哪一種、要用哪個帳號申請。依臺北市政府的規定，外部 AI 服務的帳號應該用市府公務信箱申請。

## 安裝步驟

### 第一步：下載規範包

1. 打開這個網址：https://github.com/taipei-doit/TP_AI_Agent_soul_skill （不用登入）
2. 找到綠色的「Code」按鈕，按下去
3. 選最下面的「Download ZIP」
4. 下載完成後，到「下載」資料夾找到 `TP_AI_Agent_soul_skill-main`。Windows 通常不會顯示後面的 `.zip`，圖示是有拉鍊的資料夾。
5. 在檔案上按滑鼠右鍵，選「解壓縮全部」（Windows）或直接按兩下（Mac）

解壓縮後會出現一個資料夾。打開後如果裡面還有一層同名資料夾，就再點進去，可以看到 `soul.md`、`README.md` 兩個檔案和一個 `taipei-gov-dev` 資料夾。另外還有 `en`、`ja` 兩個資料夾，是英文版和日文版，用不到，不必理會。Windows 可能只顯示 `soul`、`README`，沒有後面的 `.md`，這是正常的。

### 第二步：建立您的工作資料夾

每做一個新的網頁或系統，就開一個新的資料夾。

1. 在桌面（或您習慣的位置）按滑鼠右鍵，選「新增」→「資料夾」（Mac 是「新增檔案夾」）
2. 取一個看得懂的名字，例如 `講座報名網頁`
3. 把剛剛下載的 `soul.md` 檔案和**整個** `taipei-gov-dev` 資料夾，複製到這個資料夾裡

現在您的資料夾裡有這兩樣東西：

```
講座報名網頁
  soul.md
  taipei-gov-dev（資料夾）
```

### 第三步：讓 AI 工具在這個資料夾裡工作

AI 開發工具要「進到」您的資料夾，才能讀到規範、在裡面建立檔案。依您用的工具，照下表操作：

| AI 工具 | 操作方式 |
|---|---|
| Claude Code（桌面程式） | 打開程式，在開新對話的地方選擇資料夾，選「講座報名網頁」 |
| VS Code ＋ GitHub Copilot | 打開 VS Code，點上方「檔案」→「開啟資料夾」，選「講座報名網頁」。再打開 Copilot 對話視窗，在輸入框下方的模式選單把「Ask」改成「Agent」（Agent 模式才能幫您建立檔案） |
| Cursor | 打開 Cursor，點「Open Folder」，選「講座報名網頁」 |
| Google Antigravity | 打開 Antigravity，點「Open Folder」（開啟資料夾），選「講座報名網頁」 |
| Claude Code、Codex、Gemini CLI（終端機版） | 見下方說明 |

**終端機版的操作方式**

「終端機」是黑色或白色的文字視窗，用打字的方式操作電腦。

- Windows：按開始選單，搜尋「PowerShell」並打開。
- Mac：打開「應用程式」→「工具程式」→「終端機」。

打開後：

1. 輸入 `cd`，按一下空白鍵。
2. 用滑鼠把「講座報名網頁」資料夾拖進這個視窗，畫面上會自動出現資料夾的位置。按 Enter。
3. 依您用的工具，輸入 `claude`、`codex` 或 `gemini`，按 Enter。

（如果您用的是 Windows 的「命令提示字元」而不是 PowerShell，而且資料夾不在 C 槽，第 1 步請改輸入 `cd /d`。）

### 第四步：請 AI 幫您完成設定

接下來還要建立幾個設定檔，讓不同的 AI 工具都能找到這兩個檔案。這些設定檔有的放在隱藏資料夾裡，自己動手容易出錯，**直接請 AI 幫您做就好**。

1. 把下面框框裡的文字整段複製（在 GitHub 網頁上看的話，框框右上角有複製按鈕），貼給 AI，按 Enter 送出：

```
請幫我在這個資料夾完成「臺北市政府 AI 開發規範包」的設定，照下面步驟做，不要做其他修改。

步驟一：建立資料夾 .claude/skills/，把整個 taipei-gov-dev 資料夾（含裡面所有檔案與子資料夾）移進去，成為 .claude/skills/taipei-gov-dev/。

步驟二：soul.md 留在原位，不要移動。

步驟三：建立 AGENTS.md，內容是下面「===開始===」和「===結束===」之間的文字，不含這兩行：
===開始===
# 專案規範

本專案由臺北市政府同仁使用。開始任何工作前，必須先完整閱讀下列兩個檔案，並在整個工作過程中遵守：

- soul.md：AI 協助公務的基本立場與法規紅線，優先於其他所有規定
- .claude/skills/taipei-gov-dev/SKILL.md：臺北市政府開發規範的入口，請依其中的說明判斷工作類型，再閱讀需要的規範檔

你所使用的工具即使不支援 Skill 功能，也請直接開啟上述 SKILL.md 檔案閱讀。
開工前，請先列出工作類型與已讀取的檔案。
若無法讀取這兩個檔案，請先告知使用者，不要直接開始開發。
===結束===

步驟四：建立 CLAUDE.md，內容是下面「===開始===」和「===結束===」之間的兩行，不含標記：
===開始===
@AGENTS.md
@soul.md
===結束===

步驟五：建立 GEMINI.md，內容和 CLAUDE.md 完全相同。

步驟六：建立 .github/copilot-instructions.md，內容和 AGENTS.md 完全相同。

步驟七：建立 .agents/rules/taipei-gov.md，內容是下面「===開始===」和「===結束===」之間的文字，不含標記：
===開始===
---
trigger: always_on
description: 臺北市政府 AI 開發規範
---
@[soul.md](../../soul.md)

開發任何網頁或程式前，必須先完整閱讀 @../../.claude/skills/taipei-gov-dev/SKILL.md ，並依照其中的規定進行。
===結束===

步驟八：如果這個資料夾裡有 en、ja 資料夾（英文版、日文版規範），請刪除，只保留中文版。

完成後，請逐行列出這個資料夾裡所有檔案的路徑（包含隱藏檔），讓我確認。
```

2. AI 動手前可能會用英文詢問您是否允許，例如「Do you want to create AGENTS.md?」，請選第一個「Yes」。如果您選了「Yes, and don't ask again」，`.claude` 資料夾裡可能會多出一個 `settings.local.json`，這也是正常的。
3. 完成後，AI 會列出檔案清單。顯示方式可能和下面不太一樣（例如前面多了 `./`），只要下面這幾個都有出現就對了（`taipei-gov-dev` 資料夾裡還會有其他檔案，不用一一核對）：

```
soul.md
AGENTS.md
CLAUDE.md
GEMINI.md
.claude/skills/taipei-gov-dev/SKILL.md
.github/copilot-instructions.md
.agents/rules/taipei-gov.md
```

名稱開頭是「.」的資料夾是隱藏資料夾，在檔案總管或 Finder 裡預設看不到，這是正常的，不是 AI 沒有做。想看的話：Windows 在檔案總管上方點「檢視」→「顯示」→ 勾選「隱藏的項目」；Mac 在 Finder 裡按 Command＋Shift＋句點。

### 第五步：確認 AI 有讀到規範

請先關掉 AI 工具再重新打開，讓它重新讀取設定：

- 桌面程式：直接關閉程式再打開，並選同一個資料夾。
- 終端機版：輸入 `/exit` 按 Enter（或直接關掉視窗），再照第三步重新進入資料夾、啟動 AI。

然後問它：

```
請用三點說明，你在這個專案裡開發程式時要遵守哪些規定？
```

如果 AI 的回答提到「臺北市政府」「個資」「無障礙」「機密文書」「局處 Logo」這類內容，就代表設定成功了。

如果 AI 回答得很籠統，或完全沒提到臺北市政府，請看下面的「常見問題」。

## 開始請 AI 開發

設定好之後，就可以直接用中文告訴 AI 您要做什麼。講得越具體，做出來的東西就越接近您的需要。最好說明您是哪個機關、要做什麼、資料從哪裡來、做好給誰用。

### 五類常見的助手

以下是市府常見的五類工具，每類都附一段範例，您可以照著改成自己的業務。

**一、公務系統助手**：替承辦人處理公務系統裡重複的資料讀取與填寫，由承辦人核對後自己送出。

```
我是臺北市政府〇〇局的承辦人，每週要把 Excel 裡的補助申請資料，
一筆一筆輸入到〇〇業務系統的申請表單，大約 80 筆。
想要一個工具幫我把欄位填好，我逐筆檢查後自己按送出。
```

AI 只會幫您填寫，不會替您送出；開始前也會請您先向系統管理單位確認，這個系統允許用程式自動操作。系統由您自己登入，AI 不會向您要密碼。

**二、文書紀錄助理**：把錄音、會議資料等原始內容整理出議題和結論，依範本做成紀錄草稿或摘要，交給承辦人修正、審閱。

```
我是臺北市政府〇〇局的承辦人，每月科務會議有錄音檔和簡報，
想要一個工具整理成會議紀錄草稿，格式照本科的紀錄範本（Word）。
會議內容不涉及機密。
```

錄音含有與會者的聲音和發言，所以 AI 會先和您確認要在哪裡轉寫（例如在您電腦上執行、不連網路的轉寫工具），不會直接把錄音送到外部服務。聽不清楚的地方會標註出來，不會自己補上。

**三、資料檢核助手**：辨識、彙整文件資料，依指定的規則或參考資料逐項比對，列出檢核結果給承辦人確認。

```
我是臺北市政府〇〇局的承辦人，廠商每月送來請款資料（Excel 明細和 PDF 發票），
要比對品項、數量、金額有沒有和契約一致，把不一致的地方列出來給我確認。
```

AI 會先請您說明比對規則。檢核結果會寫明是哪個檔案、哪一列、哪個欄位，而且只標出「疑似不一致」，要不要退件由您判斷。

**四、網站巡查員**：檢查網站是否正常運作、內容有沒有更新、連結是否有效，整理成檢核結果和改善建議，由權責人員確認後修正。

```
我是臺北市政府〇〇局的承辦人，本局網站有 300 多頁，
想每週檢查一次有沒有失效的連結、超過一年沒更新的頁面，整理成報表。
```

AI 只會巡查您所屬機關自己的網站，也會放慢檢查速度，不會造成網站負擔。工具只檢查、不修改，要修正的地方由您或網站管理人員處理。

**五、資訊轉譯助理**：蒐集、整理各類資訊，做成文字或影音內容供閱讀參考，需要時也可以發布到網站、社群等管道。

```
我是臺北市政府〇〇局的承辦人，想把本局最新的公告和新聞稿，
整理成給長輩看的簡短說明，以及 Facebook 貼文草稿，我審過再自己發布。
```

AI 只用公開、可以查證的資料，每段都附上來源；不會自動發布，AI 生成的內容也會加上標示。發布前請送主管審閱。

### 其他範例

**整理 Excel 名單**

```
我是臺北市政府社會局的承辦人，每梯次的報名名單是一個 Excel 檔，
想要一個工具把所有梯次合併成一份，找出同一個人重複報名的資料。
我的電腦不能自己安裝軟體。
```

AI 會請您提供欄位名稱和幾列換成假資料的範例，**請不要把真實的名單給 AI 看**。AI 照這個格式寫好工具後，您再用工具處理真實檔案，資料不會離開您的電腦。

**活動報名網頁**

民眾要填姓名、手機、想上的課程（書法、太極拳、手機入門三選一）。
報名資料只用來通知上課，活動結束後 3 個月刪除。
```

**活動宣傳小遊戲**

我是臺北市政府〇〇局的承辦人，想做一個塔羅牌小遊戲，宣傳本局的〇〇業務，
畫面可以活潑一點，民眾玩完會看到業務重點和申請方式。
```

### 開工前與完成後

AI 開工前會先告訴您「工作類型」和「已讀取」哪些規範檔，接著可能會問幾個問題，例如「這個工具給誰用」「會不會用到個人資料」。照實回答就好；不知道的可以直接說不知道，AI 會先用預設做法處理，再請您確認。

做完之後，AI 會附上一份「交付說明」，告訴您四件事：能不能正常使用、資料存放在哪裡、有哪些限制、正式給別人使用前還要做什麼。**請一定要看完這份說明**，特別是標示〔請填入〕和「尚未確認」的地方。

## 進階：加裝中文用語檢查工具（選用）

AI 寫的中文常夾雜「默認」「用戶」「視頻」這類中國大陸用語。[zhtw-mcp](https://github.com/sysprog21/zhtw-mcp) 是國立成功大學開發的正體中文用語檢查工具（MIT 授權），會依照教育部的標點符號、字形規範及臺灣常用語檢查文字。安裝之後，AI 在交付前會自動用它檢查網頁、訊息和文件裡的中文。

您可以直接請 AI 幫您安裝。機關禁止安裝的是非法、盜版或沒有合法授權的程式；zhtw-mcp 是合法授權的開放原始碼軟體，AI 會先確認來源與檔案安全，再告訴您要裝什麼。如果機關另有規定不能自行安裝，或電腦設定讓 AI 無法安裝，再請資訊單位協助。設定步驟如下，由 AI 或資訊單位依序處理：

1. 到專案的 Releases 頁面，下載符合電腦作業系統的版本，再用專案提供的 `SHA256SUMS` 核對檔案是否正確。專案的 `latest` 版本會隨時更新，建議記錄使用的版本，或自行從原始碼編譯。
2. 在使用的 AI 工具中加入設定，例如：
   - Claude Code：`claude mcp add zhtw-mcp -- 〔zhtw-mcp 的完整路徑〕`
   - Codex CLI：`codex mcp add zhtw -- 〔zhtw-mcp 的完整路徑〕`
   - 其他工具：在專案資料夾的 `.mcp.json` 中設定，寫法請參閱 zhtw-mcp 專案的 README。
3. 請勿使用 `--verify` 選項，這個選項會把文字傳送到線上翻譯服務。

如果 AI 工具跳出權限詢問，或顯示「擋下外部程式讀取專案檔案」之類的訊息，這是 AI 工具在保護您的資料，AI 不會繞過它。AI 會說明要執行什麼、檢查哪些檔案；您確認只是檢查要交付的文字檔、沒有包含真實名單等資料後，再決定是否允許。不允許也沒關係，AI 會改用對照表檢查。

無法安裝也沒關係，AI 會改用規範裡的用語對照表自行檢查，並在交付說明寫明「未用工具檢查用語（環境沒有安裝 zhtw-mcp）」。

## 進階：讓每個新資料夾都自動套用

如果您經常開新專案，不想每次都重做第二步到第四步，可以把規範裝到您電腦的「全域設定」，以後在任何資料夾都會套用。

這個做法目前只確定 Claude Code 適用。請在 Claude Code 裡貼上：

```
請幫我把這個資料夾裡的 taipei-gov-dev 資料夾和 soul.md 安裝到我電腦的全域設定：
1. 把整個 taipei-gov-dev 資料夾複製到 ~/.claude/skills/taipei-gov-dev/
2. 把 soul.md 複製到 ~/.claude/taipei-gov-soul.md
3. 在 ~/.claude/CLAUDE.md 的最後加上一行：@~/.claude/taipei-gov-soul.md
   （如果 ~/.claude/CLAUDE.md 不存在，就新建一個）
完成後告訴我各檔案的完整路徑。
```

其他 AI 工具，建議還是每個資料夾各自設定一次，比較穩當。

## 常見問題

**問：AI 好像只讀了 README 就開工，沒有照規範做。**

答：照規範做的 AI，開工前會先列出「工作類型」「已讀取」哪些檔案。沒有列出，或「已讀取」只有 README，請直接跟它說：

```
請依照 README「給 AI 的指示」，把 soul.md、taipei-gov-dev/SKILL.md 和這次工作需要的 references 檔案完整讀完，列出已讀取的檔案後再重新開始。
```

**問：AI 好像沒有照規範做，做出來還是藍紫色的。**

答：請依序試試看：

1. 關掉 AI 工具再重新打開。
2. 直接跟它說：「請先閱讀 soul.md 和 .claude/skills/taipei-gov-dev/SKILL.md，然後依照裡面的規定重新做。」
3. 確認第四步的檔案都有建立（請 AI 列出所有檔案，包含隱藏檔）。
4. 使用 Claude Code 的話，請確認已更新到最新版本。

**問：我用的 AI 工具不在上面的清單裡，可以用嗎？**

答：多半可以。大部分 AI 開發工具都會自動讀取 `AGENTS.md`。如果設定完成後，它答不出第五步的確認問題，請在每次開新對話時，先貼上這句話：「請先閱讀 AGENTS.md，並依照其中指示閱讀 soul.md 與 SKILL.md。」

**問：AI 說它找不到我們機關的 Logo。**

答：AI 會先到機關官網找。找不到時，它會先用機關名稱的文字代替。您可以從機關官網的頁首另存 Logo 圖片，放進資料夾，告訴 AI：「Logo 檔案是 logo.png，請換上去。」

**問：AI 拒絕做我要的功能，說違反規定。**

答：這表示規範有發揮作用。AI 會說明理由，多半也會提出替代做法。常見的例子：

- 要它處理標示機密的檔案 → 機密文書依規定不能用 AI 處理
- 要它做「系統自動判斷、自動通知民眾不符資格」→ 要加上人工確認的步驟
- 要它在畫面上顯示完整的身分證字號 → 要遮蔽部分號碼

如果您認為您的需求有法律依據、應該可以做，請洽詢機關的法制或資訊單位。

**問：AI 問我「無障礙要做到 AA 還是 AAA」，我不知道怎麼回答。**

答：直接說「依你的建議」就好。AI 會依網頁的功能判斷：功能單純的頁面（例如只有一個表單）建議做到最高的 AAA；功能複雜的（例如有地圖）至少做到 AA。

**問：AI 做好了，可以直接放上網路嗎？**

答：**不行。** 請先：

1. 自己實際操作一遍，確認功能正常、文字正確。
2. 看完 AI 的交付說明，補上所有標示〔請填入〕的地方。
3. 交給機關資訊單位，由他們協助設定主機、HTTPS、資安檢測、無障礙檢測後再上線。

**問：我可以把民眾的真實資料給 AI，讓它幫我測試嗎？**

答：**不可以。** 依行政院和臺北市政府的規定，不得把個人資料提供給外部 AI 服務。請用假資料測試，例如「王小明」「0912-345-678」。AI 也會主動用假資料。

**問：檔案名稱一定要是 `SKILL.md` 嗎？可以改成小寫嗎？**

答：請維持 `SKILL.md`（全部大寫），Claude Code 只認得這個檔名。`soul.md` 則維持小寫。

**問：規範更新了怎麼辦？**

答：重新從第一步下載。新的 `soul.md` 直接覆蓋舊的。`taipei-gov-dev` 資料夾先放進您的專案資料夾最上層，再請 AI 幫您：「請刪除 .claude/skills/taipei-gov-dev 資料夾，改用最上層新的 taipei-gov-dev 資料夾移進去取代。」

## 給機關資訊單位的說明

- Skill 採用 Agent Skills 格式，資料夾 `taipei-gov-dev/`：`SKILL.md`（YAML frontmatter，`name` 為 `taipei-gov-dev`）是入口，依工作類型（文件與資料處理工具、小工具、對外網頁、表單、系統、含 AI 功能）指示 AI 讀取 `references/` 中需要的規範，範本在 `templates/`。AI 只會載入需要的部分，做 Excel 工具時不會套用網站規範。
- `references/` 的規定標有〔法〕〔府〕〔建議〕，分別代表法律明文、行政院或市府規定、本規範建議；法規條號、文號與原文網址集中在 `references/legal-sources.md`。
- 整個資料夾只放一份在 `.claude/skills/taipei-gov-dev/`。Claude Code、VS Code Copilot、Cursor 會從這個位置載入 Skill；Codex CLI、Gemini CLI 不掃描 `.claude/skills/`，改由 `AGENTS.md`、`GEMINI.md` 指示直接讀取檔案。不另外複製到 `.agents/skills/`，是為了避免 VS Code 同時讀到兩份同名 Skill，也避免更新時兩份內容不一致。
- `CLAUDE.md`、`GEMINI.md` 的 `@` 匯入語法只有 Claude Code 和 Gemini CLI 看得懂。GitHub Copilot 也會讀這兩個檔案，但只會看到文字，不會出錯；它另外從 `AGENTS.md` 與 `.github/copilot-instructions.md` 取得完整指示。
- Google Antigravity 會讀 `AGENTS.md`、`GEMINI.md` 與 `.agents/rules/*.md`，但只用 `.agents/skills/` 載入 Skill，`GEMINI.md` 裡的 `@soul.md` 也只會變成檔案路徑、不會載入內容。因此另建 `.agents/rules/taipei-gov.md`（`trigger: always_on`），用 `@[soul.md](../../soul.md)` 把 soul.md 全文嵌入，SKILL.md 則以路徑指示讀取。Antigravity 單一規則檔上限 24 KB（嵌入後計算），soul.md 若日後擴寫，請注意不要超過。
- 其他未列出的工具（例如 Windsurf、Cline、JetBrains AI Assistant），多半支援 `AGENTS.md`；不支援時，請在每次對話開頭先輸入「請先閱讀 AGENTS.md，並依照其中指示閱讀 soul.md 與 SKILL.md」。
- `soul.md` 透過 `CLAUDE.md`、`GEMINI.md` 的 `@` 匯入語法，在每次對話開始時載入；Codex、Copilot、Cursor 則由 `AGENTS.md` 指示讀取。Skill 只在 AI 判斷相關時才會載入，所以法規紅線放在 `soul.md`，每次對話都會讀到。
- Codex CLI 讀取 `AGENTS.md` 的預設上限是 32 KiB，因此 `AGENTS.md` 只放指引，不要把兩份檔案的全文貼進去。
- 機關若有自己的代表色、Logo 規範或內部資安規定，可以在 `taipei-gov-dev/references/` 對應的檔案（例如 `web-ui.md`、`security.md`）或 `soul.md` 末尾增加「本機關補充規定」一節。主色更換後，請重新計算文字對比度。
